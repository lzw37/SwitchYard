## 先查看界面

需要 Node.js **20.19+（20.x）或 22.12+**；运行仓库内直接加载 TypeScript 的 Node 测试时使用 **22.18+ 或 24**。请保留整个仓库的相对目录结构，前端依赖旁边的 `SwitchYard.StationLayout/frontend`。

在仓库根目录打开终端：

```powershell
cd switchyard-vue
npm ci
npm run dev -- --host 127.0.0.1
```

开发端口固定为 `5173`；端口被占用时会明确报错，不会自动切换到其他端口。可打开以下本地示例，无需配置业务数据库：

- [工作区样式预览](http://127.0.0.1:5173/dev/workspace-style.html)：使用生产组件和本地示例数据。
- [作业过程交互示例](http://127.0.0.1:5173/dev/operation-process.html)：示例修改只在当前页面内存中保存。

工作区预览支持 `?page=hump&lang=en` 和 `?page=course&lang=en`；过程示例支持 `?lang=en`。这些开发入口不包含在正式构建中，也不代表后端业务验证。

## 启动完整系统

API 的目标框架为 **.NET 8**，CapacityAgent 为 **.NET 10**，独立站场模块及其烟雾测试同时面向两者。完整构建建议准备 **.NET 10 SDK**，运行 API 和 .NET 8 测试还需 **ASP.NET Core 8 运行时**。此外需要配置好的 SQLite 或 MySQL 数据库和前端；能力求解另需运行 CapacityAgent。

1. 按[首次启动说明](../guides/Getting-Started.md)配置后端监听地址、JWT、数据库及所需表结构。
2. 从仓库根目录启动 API：

   ```powershell
   dotnet run --project SwitchYard.WebApi/SwitchYard.Service --no-launch-profile
   ```

3. 启动前端。开发环境默认跟随浏览器地址中的主机名，通过 HTTP `7297` 访问 API；例如打开 `http://localhost:5173` 时请求 `http://localhost:7297`，通过局域网地址打开时请求同一主机的 `7297`。如需连接其他 API，可在 `switchyard-vue/.env.development.local` 中显式覆盖：

   ```dotenv
   VITE_API_BASE_URL=http://localhost:7297
   ```

4. 准备好业务模板和账号后，注册或使用已有账号登录，创建或选择有权限的实例。首次建表不会自动提供完整的教学数据：当前新建用户流程依赖默认驼峰模板 `001`，空库缺少该模板时不能直接完成注册；详见首次启动说明。新实例的数据需要逐步录入。
5. 要使用「模型求解」，按[代理说明](../development/capacity-agent.md)启动并连接代理，再选择可用模型。

API 的实际监听地址来自 `WebApi:Hosts`，程序会显式调用 `UseUrls`；不能只根据 `launchSettings.json` 或 `--launch-profile` 判断端口。开发配置默认监听 `http://0.0.0.0:7297`，保留 `http://localhost:5102` 作为兼容入口。无需绑定某个固定网卡 IP，换网络或重启后仍使用原主端口 `7297`；浏览器请使用 `localhost` 或本机实际地址访问。以启动日志中的监听地址为准。

前端 `VITE_API_BASE_URL` 是启动/构建时配置。修改后需重启开发服务或重新构建。接口路径并非统一带 `/api`：认证使用 `/api/Auth/...`，业务模块使用 `/Hump/...`、`/StationLayout/...`、`/OperationPlan/...` 等，因此这里应填写服务根地址。

## 常见问题

| 现象 | 先检查 |

| 页面能打开但业务列表加载失败 | API 是否运行、`VITE_API_BASE_URL` 是否对应监听地址、是否已重启开发服务、登录和实例权限 |

## Sketch Layout Planning（布置图分析）

「作业流程设计」工具栏的「作业数量设置」打开集中编辑表格，每项流程对应一行数量（1–1000000 的整数），统一应用于该流程的全部作业内容。点击「应用」一次更新全部流程，取消或关闭对话框不改变原值；批量修改支持一次撤销/重做，随后点击顶部「保存方案」持久保存。

从首页进入 `/sketchlayout`，使用现有 hump 账号登录。普通用户管理自己的方案，管理员可管理全部方案；每次 API 请求都会从 hump 核验账号是否有效及当前角色。业务数据保存在独立的 `SketchLayoutDatabase`，不创建或复制用户表。

方案名称和说明统一在「方案管理」中点击对应行的「编辑」修改，主页面不再显示输入行。点击「编辑」后直接在该行的名称、说明单元格输入，操作区切换为「保存 / 取消」；保存后管理列表与顶部方案选择器同步更新，取消不改变数据。编辑其他方案不会切换当前画板，编辑当前方案的信息会保留尚未保存的图形、流程修改及其撤销/重做记录。

点击「新建方案」直接在管理表格顶部新增草稿行，填写名称和说明后点击「保存」创建；「取消」移除草稿行，保存失败保留输入以便重试。已有画板时，新建方案不会切换画板或丢弃未保存内容，点击新方案的「打开」再切换；创建首个方案时自动载入。管理表格的新建、打开、编辑、删除、保存和取消操作统一使用程序现有的圆形图标按钮，悬停显示操作名称。

1. 新建方案，「布置图设计」默认为普通模式：点击元素选中，拖动空白处平移，滚轮缩放。点击多边形、出入口或作业进路按钮进入绘图模式；按 Esc 取消未完成的绘制并回到普通模式。多边形逐点绘制，点击首点或 Enter 闭合；圆圈代表出入口。绘制作业进路时点击圆心、多边形顶点或边中点，途中点击空白添加进路锚点，最后点击目标端点。普通模式可拖动设施、顶点和锚点，双击通道就地重命名，Shift＋双击通道添加锚点，右键锚点删除；支持撤销和重做。
2. 在「作业流程设计」新建流程方案，每套方案可包含多项作业内容。中间纵向列表同时列出所有作业内容的名称、每次耗时、总耗时与草稿状态，点击「新增作业内容」添加；选中卡片后，在画板依次点击设施，仅向当前作业内容追加步骤。作业数量可在作业内容列表顶部设置，也可通过「作业数量设置」集中调整；当前流程方案的所有作业内容共用此数量，右侧可修改作业内容名称、每步停留时间和来向通道通行时间（秒），也可复制或删除当前作业内容。若两个设施之间有多条通道，可在步骤中选择。每个布局可保存多套流程方案，并可整体复制、重命名和删除；流程方案用于分组编排和统一设置作业数量，全部作业内容在整张布置图的统一分析时段内独立作业。未完成作业内容可保存为草稿，分析时要求所有流程方案中的每项作业内容至少两步。修改后点击顶部「保存方案」。
3. 「布置图形分析」直接合并当前布置图的全部流程方案，无需选择流程方案。设置统一随机出发时段与 SLP 分级阈值，生成整张布置图的作业关系和冲突结果。SLP 汇总所有作业内容每次转移的数量，累加双向作业量，以全图最大设施对作业量归一化；默认 A/E/I 下限为 0.8/0.5/0.2，较低正流量为 O，零流量为 U。冲突检查包括不同流程方案的作业内容组合，同名或同 ID 的跨方案作业内容分别计入，结果保留流程方案与作业内容名称以便定位。这些阈值是本模块的可配置规则，不是 SLP 的固定标准；非作业关系及 X 关系不在本次计算内。方法参考 [Richard Muther & Associates](https://richardmuther.com/systematic-planning-methods/)。

作业流程设计从左到右为画板、作业内容纵向列表、作业内容属性与步骤。列表左侧分隔线调整画板与列表的宽度分配，右侧分隔线调整列表与属性面板的宽度分配；支持拖动、方向键微调和双击恢复默认。作业内容列表独立滚动，窄窗口可横向滚动三栏区域。宽度调整属于当前界面的视图状态，不修改方案数据。「布置图设计」和「作业流程设计」会自动占满顶部工具栏、标签栏以外的窗口空间；画板及侧栏随窗口高度伸缩，作业内容列表和步骤区在各自栏内滚动。

作业内容的步骤列表按「设施停留 → 作业进路走行 → 设施停留」交替显示并连续编号。设施卡片仅编辑该设施内的停留时间；进路卡片单独显示连接名称、起终设施及走行时间，有多条可用进路时可切换。作业内容列表项在同一行显示每次耗时和总耗时（流程方案数量乘以该作业内容每次耗时），设施、连接及停留与走行时间明细在右侧步骤中编辑。为兼容已有文档，存储仍为 `steps[].dwellSeconds` 与 `steps[].incomingLinkId/travelSeconds`；后两项表示进入该设施之前的独立走行步骤，不属于设施停留。截断设施步骤时同步移除进入该设施的进路及后续步骤。

作业内容冲突模型假设每次作业独立、均匀地在 `[0,H]` 内出发，步骤时长固定，作业可延续到 H 之后。设施及通道均为单容量互斥资源；同向、对向及几何交叉/重叠的通道均检查占用冲突。分析使用当前显示模式对应的路径，每段倒角圆弧采用 24 等分近似，交叉通道在整个通行期间互斥，因此是保守估计，不等同于碰撞概率。设两作业起始时刻差为 Δ，对占用区间 `[a,b)`、`[c,d)`，冲突条件为 `a-d < Δ < b-c`。先合并所有冲突区间，再按两个独立均匀分布之差的三角分布积分，避免重复资源重复计数。不同作业内容的作业对数为 `n×m`，同一作业内容为 `n×(n-1)/2`。展示单对作业至少一次冲突概率及期望冲突作业对数；后者不是系统至少一次冲突概率。

分析页另有「进路交叉点冲突与排队分析」：仅使用已保存交叉点的 `sourceLinks`，汇总全部流程方案中每条进路的通行次数 `Nᵢ`（重复经过也计入），到达率 `λᵢ=Nᵢ/H`。展开交叉点可独立设置各进路在该交叉区的占用时间 `mᵢ`，默认采用所有流程中该通道按通行次数加权的平均通行时间；「恢复自动」清除覆盖值。选择概率模型后点击「保存并分析」。总体值为 `ΣNᵢPᵢ/ΣNᵢ`，表示随机一次通行遇到其他参与进路至少一次占用重叠的概率，不是全时段至少一次冲突概率，也不是排队等待时间。

- 泊松到达＋固定占用（默认）：`Pᵢ=1-exp(-Bᵢ-Rᵢmᵢ)`，其中 `Bᵢ=Σⱼ≠ᵢ λⱼmⱼ`、`Rᵢ=Σⱼ≠ᵢ λⱼ`。
- 泊松到达＋指数占用：输入平均占用时间，`Pᵢ=1-exp(-Bᵢ)/(1+Rᵢmᵢ)`。按平稳、独立带标记泊松过程推导：开始时刻无既有占用的概率为 `exp(-Bᵢ)`，再对本次指数时长内无新到达的概率取期望。对向每次作业各有独立时长，不能将整个到达流替换为共享一个随机时长。平稳 M/G/∞ 占用数的依据见 [MIT Queueing Theory，第 5 页](https://ocw.mit.edu/courses/15-763j-manufacturing-system-and-supply-chain-design-spring-2005/22f4805864deb06eee85acc1601463ba_queueing_note.pdf)。
- 均匀到达＋固定占用：各进路固定 `Nᵢ` 次作业，各次在 `[0,H]` 独立出发。给定所选作业时刻 `u`，其他进路冲突窗口长为 `ℓᵢⱼ(u)=min(H,u+mᵢ)-max(0,u-mⱼ)`，计算 `Pᵢ=1-∫₀ᴴ ∏ⱼ≠ᵢ(1-ℓᵢⱼ(u)/H)^Nⱼ du/H`。先按条件概率组合再积分，处理边界及占用时间超过 H 的情况。自适应积分绝对容差为 `1e-9`，深度上限 30，每点最多 100 万、全图最多 500 万因子求值；达到上限显示无法计算，不返回未收敛概率。

同一标记中的参与进路视为两两互斥，各次到达独立；同作业内容重复经过或使用多条参与进路时会提示相关性近似。冲突概率不计同一进路内追踪间隔、排队、优先权或调度避让；新增排队指标按下述独立模型计算。泊松模型次数用于估计到达率，并包含分析时刻之前尚未结束的占用；均匀模型固定次数，不含时段开始之前的作业。无通行量、来源缺失、来源已删除分别显示原因；仅一条参与进路有作业时，跨进路冲突概率为 0。移动标记、隐藏标记或改变曲线显示不改变其已记录的分析来源，计算不会生成交点。修改几何后应核对已有标记。

每个交叉点新增平均排队延误 `Wq`（秒）、平均排队长度 `Lq`（项）和负荷率 `ρ`。按独占单服务台、先到先服务（FCFS）、无限等候空间计算，包含同一进路作业的排队；等待时间不含实际占用时间，队长不含正在通过的作业。继续使用统一流程方案数量和交叉区占用时间，设施停留时间不计入服务时间；各交叉点分别评估，不传播上下游延误，也不模拟优先级调度。

- 泊松到达采用 M/G/1：`ρ=Σλᵢmᵢ`，`Wq=ΣλᵢE[Sᵢ²]/[2(1−ρ)]`，`Lq=(Σλᵢ)Wq`。固定占用使用 `E[Sᵢ²]=mᵢ²`，指数占用使用 `2mᵢ²`，保留进路间服务时长差异。参考 [MIT M/G/1 与 P-K 公式](https://web.mit.edu/urban_or_book/www/book/chapter4/4.7.html)。`ρ≥1` 时状态为 `unstable`，显示“无有限稳态”，延误及队长返回 `null`，负荷保留实际值而非截断为 100%。
- 均匀到达按固定次数在 `[0,H]` 独立抽样，从空队列开始进行可复现 FCFS 仿真。`Wq` 平均所有作业的完整等待（含 H 之后的等待）；`Lq=∫₀ᴴQ(t)dt/H`，仅对分析时段积分，因此不套用稳态 Little 公式。负荷仍为 `ΣNᵢmᵢ/H`，超过 100% 时仍可给出有限批次估计。每点最多 2 万次通行、64–2048 次重复、200 万个仿真事件，全图最多 800 万个事件；不足最低重复次数或规模超限时返回 `calculation-limit`，只保留负荷。展开行显示重复次数及两项估计的标准误。固定随机种子及来源排序使相同输入可复现。

分析响应的 `crossingRisks[].queue` 包含 `model`（`mg1-fcfs` / `finite-uniform-fcfs`）、`status`、`loadRatio`、`meanDelaySeconds`、`meanQueueLength`、`simulationRuns`、`delayStandardErrorSeconds` 与 `queueLengthStandardError`。无作业三项指标均为 0；来源缺失或删除时不显示数值。排队与冲突概率分别报告计算状态，某项计算超限不掩盖另一项结果。指标是派生结果，无需数据库迁移。

`analysisSettings.crossingModel` 保存 `poisson-fixed`、`uniform-fixed` 或 `poisson-exponential`；旧文档默认 `poisson-fixed`。`crossings[].sourceLinks[].occupancySeconds` 为可空占用秒数覆盖值（0.01–31536000），`null` 使用自动值。分析接口新增 `crossingRisks[]`，包含每个交叉点及各参与进路的次数、到达率、占用时间、条件概率、总体概率和状态。参数随文档保存并支持撤销、重做；无需数据库表迁移。

布置图画板的「捕捉与网格」沿用 StationLayout 的点阵网格：默认间距 20，可设置为 1–500 个画板坐标单位，显示开关与网格追踪开关独立。新建多边形顶点、出入口圆心、进路锚点以及拖动顶点/锚点时会吸附到网格；整体拖动设施时吸附首顶点或圆心，同时保持设施形状。画布可向任意方向延伸，设施、锚点和交叉标记支持负坐标及原 2400×1600 范围之外的位置；网格始终覆盖当前视野。打开方案或点击「全图」时按全部图元定位，包含连接锚点和可见交叉标记；保存、流程设计及分析沿用相同坐标，不裁剪或移动已有图元。缩小时自动稀疏显示网格点，吸附仍使用设定间距。网格设置随方案保存并支持撤销/重做；打开旧方案默认启用网格，不改变已有几何坐标。

工具栏的「显示作业进路名称」开关控制进路名称：开启时全部显示，关闭时仅显示选中进路的名称；选中名称加粗。默认关闭，保留旧方案的显示方式。设置随方案保存并支持撤销/重做，流程画板仍保留当前作业内容的步骤标注。

作业进路的锚点定义折线拐点。工具栏的「曲线显示」开关默认开启，按 StationLayout 的相切圆弧方式倒角；关闭时显示经过锚点的折线。默认倒角半径为 100 个画板坐标单位，短线段或相邻倒角空间不足时自动缩小，避免倒角重叠。切换不改变锚点坐标，设置随方案保存并支持撤销/重做；中部箭头跟随当前路径的长度中点和方向。

工具栏另有独立的「多边形倒角」开关，默认开启。多边形默认倒角半径为 150 个画板坐标单位。仅对实际内角为直角或钝角的顶点使用相切圆弧倒角，锐角、平角和凹角保留原样；闭合边与短边上的相邻倒角会自动缩小以避免重叠。关闭时显示原始多边形。倒角不改变保存的顶点和作业连接端点，选中后仍编辑原顶点；双击倒角边缘会将新增顶点投影到原边。该开关随方案保存、支持撤销/重做，作业流程画板沿用同一显示设置。

「进路交叉」按钮按当前折线／圆角曲线一次性计算不同作业进路的交点，并生成独立的红圈标记；公共端点与重合区段不生成标记，同位置交点合并。仅切换「显示进路交叉」不会计算交点；编辑进路线或倒角显示也不会移动已有标记。每次点击按钮都会清空原有交叉标记，按当前交点重新生成，名称从「进路交叉 1」开始编号，半径恢复默认值，占用时间设置重置；当前没有交点时也会清空旧标记。整个替换操作可一次撤销，恢复原有标记及其属性。每个标记记录生成时参与进路的 ID 与名称，属性面板列出这些进路；进路改名时显示现名及生成时名称，删除后仍保留来源名称并标注已删除。标记可选中、拖动，或在右侧设置名称、中心坐标和红圈半径（5–200），也可删除；显示开关与标记均随方案保存并支持撤销/重做。每个方案最多 1000 个标记，重新生成超过上限时保留原有标记，不进行部分替换。标记不作为流程步骤，但其来源用于交叉点冲突概率计算。

布置图形分析页采用左右分栏：左侧以「冲突分析」「作业关系」两个 Tab 显示结果和参数，右侧为共用的布置图画板，支持平移和缩放。中间竖向分隔线可拖动调整宽度，双击复位；左侧内容独立滚动，切换 Tab 时右侧画板保持可见。作业进路按两端设施对的 AEIOU 等级着色，悬停显示等级、相对作业强度和设施对双向总流量（同设施对的多条进路共用此等级）。保存的交叉圆圈按负荷率的 0–75% 明亮连续色谱填充，75% 及以上固定使用最高档红色（包括超过 100% 的情况），填充不透明度为 32%。悬停显示负荷率、冲突概率及来源进路；未计算或无有效负荷数据用灰色表示，不与 0% 混淆。排队仿真超限但负荷已知时仍按负荷着色。表格中的交叉点、进路及作业内容冲突概率数字按 0–100% 色谱着色，负荷率数字采用与圆圈一致的 0–75% 色谱。两个色谱带图例，切换 Tab 不隐藏画板。分析视图显示全部已保存交叉点，包括设计页中隐藏的标记；不修改设计颜色、可见性或对象属性。参数变更使分析结果失效时，画板同步清除旧色谱结果。

「作业关系」卡片上方显示设施对关系表，下方以 Richard Muther Activity Relationship Chart 的菱形三角矩阵呈现相同结果，按布置图设施顺序编号，每对设施只出现一次，包括零流量 U 关系。为便于对照作业分析，菱形上格为 AEIOU 等级，下格为双向总作业量（替代传统关系图的原因代码）；悬停或键盘聚焦可查看完整名称、精确总量、相对强度及正反向流量，并突出对应设施行。该图只反映已计算的作业关系，不推断非作业原因或 X 关系。表格与活动关系图之间的横向分隔线可上下拖动，在固定区域内调整两者的高度分配，双击恢复默认高度；两部分保留独立滚动和最小可用高度。较大的矩阵可在图内滚动。分析分栏设有最小宽度，极窄窗口可横向滚动查看。

画板与右侧属性面板左右平铺，中间的竖线可拖动调整宽度（双击恢复默认宽度，也可使用方向键调整）。普通模式双击设施、出入口、交叉点或对象名称可就地重命名，Enter 保存、Esc 取消，离开输入框时保存有效名称；直接双击作业进路也可重命名；Shift＋双击作业进路添加锚点，或使用属性面板中的“添加锚点”。多边形边线上的双击仍用于添加顶点，双击其名称可重命名。普通模式点击图面对象后，面板自动显示相应属性；选中对象改变边缘颜色、名称加粗，不显示外框。可编辑多边形的名称和顶点坐标、出入口的名称/圆心/半径、作业进路的名称和进路锚点；进路端点显示其连接的设施与位置。坐标修改会保留已有端点引用，无效几何会提示并还原。点击空白或关闭按钮清除选中，右侧显示选择提示；修改支持撤销/重做并随方案保存。

流程数据层级为 `plans[] → chains[] → steps[]`：流程方案保存 `executionMode: "parallel"` 和唯一的 `quantity`，每项作业内容独立保存 ID、名称和有序步骤。布置图根节点的 `analysisSettings` 保存全图共用的分析时段与 SLP 阈值。作业内容之间没有前后执行依赖，也不要求同时出发。旧文档缺少 `executionMode` 时按平行语义读取；缺少 `analysisSettings` 时，若原有流程方案的参数一致则沿用，不一致则采用统一默认值（3600 秒，A/E/I 为 0.8/0.5/0.2），与方案排序和当前编辑选择无关。统一参数可在分析页调整并保存；已有作业内容的步骤保持原样，无需迁移数据库表。

每项流程方案只有一个作业数量，在「作业内容」区域顶部统一设置；所有作业内容及其设施停留、进路走行步骤均使用此数量，列表项和右侧步骤不再分别设置或重复显示数量。修改后，各作业内容总耗时、SLP 作业量和交叉点通行次数同步采用该数量，支持保存、撤销和重做。旧文档缺少流程方案 `quantity` 时，采用第一项作业内容原有数量（空方案默认 1），移除作业内容数量字段；已有流程方案数量优先。此转换在读取时完成，保存后持久化，无需改动数据库表。分析中累计作业内容执行次数为各流程方案的数量乘以其作业内容数后求和；多个作业内容共用资源或重复经过资源时继续累加通行量。

方案以单个版本化 JSON 文档保存于 `sketchlayoutscheme`，画板及全部流程方案原子写入。PUT 与 DELETE 必须携带当前 revision；版本不符返回 409。删除被流程引用的设施/通道会被拦截，编辑会使分析结果失效。

开发默认自动创建独立 `sketchlayout.db`（SQLite），可通过 `SketchLayoutDatabase__SqlliteConfig__DatabaseFile` 指定持久目录。生产默认使用 MySQL 数据库 `sketchlayout`：先执行 `scripts/deploy/sketchlayout-database.sql` 并为服务账号授予该库权限，配置 `SketchLayoutDatabase__MysqlConfig__Host/Port/Database/Username/Password`（模板见 `scripts/deploy/switchyard-api.env.example`），表结构随服务启动自动初始化。既有部署升级时也需补充这些环境变量。

API：`GET/POST /SketchLayout/schemes`；`GET/PUT/DELETE /SketchLayout/schemes/{id}`；`POST /SketchLayout/schemes/{id}/analysis`（取代按流程方案分析的旧地址）。分析结果包含 `scope: "all-plans"`、流程方案数、作业内容数及作业总量；冲突条目使用流程方案 ID 与作业内容 ID 联合定位。PUT 接收 `{ revision, document }`，DELETE 使用 `?revision=N`；流程方案增删改通过 document.plans 一并保存。输入上限为 200 个设施、400 条通道、50 套方案，每套 100 项作业内容/1000 步。全图分析所用曲线最多 5000 个近似线段，最多 5 万组作业内容组合与 500 万组占用比较；超过限制会明确报错，不会省略某套方案或返回部分结果。
