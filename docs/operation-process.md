# 作业过程编排

作业过程编排位于「通过能力 → 作业计划」，与列车模板、列车作业计划、计划图和分析子页签共同使用。完整业务流程见[通过能力使用指南](../doc/Capacity.md)。

## 使用

进入「通过能力 → 作业计划」，选择实例、站场方案和作业计划，再进入「作业过程编排」。点击「加载示例」得到一个未保存的新模板；点击活动、两端事件圆点、次序箭头或锚标记，在右侧修改对象属性。编排内容撑满选项卡的可用宽高，从左到右依次为编排图、属性编辑和对象列表；活动、事件、次序、锚表格位于最右侧，可点选对象编辑。各栏独立滚动，窄窗口下保持并列并提供横向滚动。

顶部使用紧凑工具栏：模板名称显示在加宽的小尺寸下拉框中，旁边保留保存状态，新建、加载示例、保存和删除使用小圆形按钮，悬停或键盘聚焦可查看名称。模块标题、独立模板名称和对象总数不再重复占用顶部空间；右侧对象列表的标签仅显示「活动、事件、次序、锚」，不附带数量。模板名称仍可在属性编辑中修改。

编排图与属性栏、属性栏与对象列表之间提供统一的竖向分隔条，左右拖动可调整栏宽。分隔条可通过 Tab 聚焦，再用左右方向键调整；Shift 加大步长，Home / End 调整到最小／最大宽度，Enter 或双击恢复默认宽度。这些布局操作不会修改模板内容。

主界面右上角的 EN / 中按钮切换界面语言；编排工具、对象类型、属性名、空状态和交互提示提供中英文显示。活动名、模板名等业务数据按保存内容展示，不随界面语言自动翻译。

添加次序采用两步连线：点击「添加次序」后，仅活动的结束事件亮起；点击前序结束事件后，该事件变为实心圆点，仅其他活动的开始事件亮起供选择后序节点。悬停目标事件显示从结束事件指向开始事件的虚线箭头，点击目标后才新增次序并恢复正常显示，默认间隔为 0，可在右侧继续调整。Esc 或「取消添加次序」可放弃未完成的连线；同一活动的开始事件、结束事件、独立事件及与前序相同的事件不能作为此次连线的目标，连线过程中暂停其他对象的编辑和拖动。循环依赖及时刻约束仍由模板校验检查。

编排工具栏的「隐藏对象列表 / 显示对象列表」按钮切换最右侧列表，隐藏时画布自动扩展。重新显示后保留当前列表标签及对象选择；此开关仅改变页面布局，不产生模板修改。

移动活动包括 Arrival、Departure、Shunting、Locomotive，备选进路按同名进路类型筛选。Dwelling 使用备选轨道。所选进路、轨道、锚必须来自相应备选列表。模板使用当前站场方案的 Node、Link 和 StationRoute；当前代码没有独立 Track 表，因此 Track 引用现有 Link。不会向已有站场写入示例轨道或节点。

移动活动图形及活动列表显示全部备选进路名称，随属性修改即时更新，长名称换行，未选择时显示「备选进路：未设置」。属性面板不显示「选定进路」，每条备选进路的端点锚可在对应折叠项中单独配置。数据结构保留 `selectedRoute` 兼容已有模板，移出备选列表时清空该值；添加候选不会自动选定进路，也不会修改事件地点。

活动的开始、结束事件在创建时确定，属性面板仅作只读展示，保存接口也禁止更换已有活动的起止事件关联；修改活动名称时，起止事件名称自动更新为「活动名称开始」「活动名称结束」，事件 ID、时刻、地点和锚保持不变。事件属性不显示发生时刻，图中不显示「时刻待定」；既有非空时刻数据及校验仍保留。停留活动的备选轨道仅包含真实名称非空的轨道，`null`、空字符串或全空白名称均不允许，界面不显示「选定轨道」。数据结构保留 `selectedTrack` 以兼容既有模板，移出备选列表时会清空其选定值。未命名轨道仍可用于进路及锚引用。

事件地点改为只读的「备选 Node」：开始事件取所属活动全部备选进路的起点，结束事件取终点；相同节点去重，共享事件汇总对应端点，仅使用当前站场的有效节点。修改备选进路后即时更新，保存和读取时后端重新生成 `nodeList`，客户端提交值不能覆盖该规则。没有备选进路的停留或独立事件显示空列表。旧 `nodeID` 保留兼容但不再决定候选；候选非空时，事件锚必须连接其中任一节点，界面会清理因候选调整而失配的事件锚。

备选轨道选项、已选标签、停留活动图形和活动列表中的候选名称均直接显示 `Link.Name`，不以 Link ID 或「轨道 + 编号」补齐。图形中的备选股道随属性编辑即时更新，名称过长时换行，未选择时显示「备选股道：未设置」。成功加载站场目录后，旧模板中的未命名或已删除 Link 引用会从停留候选中移除，并作为未保存的草稿修正提示；保存该模板后才写入数据库。

时间采用**相对于模板起点的分钟数**，事件时刻可以留空。`interval` 是前后事件的**最小间隔分钟数**，服务端同时接受原需求拼写 `intervel`。设置事件时刻后，保存会检查活动时长范围及次序间隔。模板内的进路起终点锚配置均可留空。

## 从作业过程生成列车模板

在「列车模板」列表上方点击「从作业过程生成」，选择当前实例、站场方案及作业计划下已保存的作业过程，然后生成。尚未保存的编排草稿不会出现在选择列表中。生成成功后刷新并展开新列车模板，不覆盖已有模板，也不修改原作业过程。

按现有列车模板字段转换：每个活动生成一条作业模板，保留活动名称及全部备选进路；最小时长从分钟转换为整数秒并向上取整。停留活动尝试匹配已有的停留进路，进路必须恰好对应其中一条备选股道，不会把经过该股道的接发车进路当成停留进路。未匹配进路的活动仍会生成，并在结果中提示先补充进路再用于计划或求解。原有求解器对空进路候选会回退到全站候选，因此此提示需要处理。

作业排列采用活动起止事件和次序关系组成的事件图拓扑顺序；同序时保留稳定顺序，不使用画布坐标。原模型中的最大时长、事件时刻、次序间隔、并行关系和锚无法完整映射到现有顺序作业模型，仍保留在原作业过程，生成结果会说明这些限制。列车数量默认 1、列车类型留空、固定作业关闭，可在生成后继续编辑；旧字段长度上限导致的名称缩短会明确提示。

服务端 `POST /OperationPlan/GenerateTrainTemplateFromProcess` 接收 `instanceID、stationSchemeID、operationPlanID、processTemplateID、revision`，只从数据库读取已保存版本，并在同一事务中新增列车及全部作业模板。源版本过期返回冲突，任一写入失败时全部回滚。响应为 `trainTemplate、movementCount、warnings`。

## 从作业过程批量生成列车作业计划

在「列车作业计划」工具栏点击「从作业过程生成」，选择当前作业计划下已保存的过程，设置生成数量与时间范围。新入口追加列车及其全部活动，不覆盖已有列车；旧「自动生成」入口仍按原有规则重建计划。数量为 1–1000，本批活动总数上限 20000，时间支持跨日（最多 7 天）。

多个列车的起点沿用原平均定位公式：按本批全部移动数计算均匀时间槽，预留最长最小时长，使用每列首个活动对应的槽位定位该列车的起点。固定满足约束的列车起点后，对同一列车的完整事件图统一求最早可行时刻，使各事件在全部约束下尽早发生。次序间隔为 0 且无其他约束阻碍时，前后事件直接衔接；最小／最大时长、相对固定事件时刻、共享事件和任意端点之间的最小次序间隔仍须满足。平均起点定位是排布目标，约束与时间范围是硬条件；不可行时整批回滚，不生成残缺列车，也不把并行关系强行改成顺序。初始排布不替代跨列车轨道电路占用冲突优化。

每列车在新增 `trainprocesssnapshot` 表中独立保存完整源过程、来源版本、活动到移动映射、排定事件时刻和停留股道选择。源过程后续修改或删除不会改变已生成列车。停留直接使用有名称的备选股道；移动选择满足事件地点和锚约束的备选进路，资源缺失时拒绝生成。选中列车后点击「过程约束」可查看全部对象；绑定过程的移动不能在旧表中单独增删、重排或修改约束字段，可修改源过程后重新生成或删除整列车。

`POST /OperationPlan/GenerateTrainOperationPlanFromProcess` 接收作用域、`processTemplateID、revision、trainCount、startTime、endTime`，返回完整当前计划及 `processConstraints、generatedTrainIDs、warnings`。`GetTrainOperationPlan` 同样返回约束快照。列车删除、计划复制／改 ID／删除、旧入口重建均同步处理快照。

能力求解输入会读取完整事件图和精确时长范围，停留股道在求解内部映射到关联轨道电路，不写入虚构的站场进路。过程列车使用显式事件约束，普通列车继续使用旧连续移动规则；共享事件同时约束时刻及物理地点／锚。求解结果保存为饱和计划时保留约束副本与停留股道。含过程约束的求解任务需要模型版本 **2.0.0 或以上** 的 CapacityAgent，服务端会拒绝向旧版本提交，防止旧代理忽略约束。

## 列车列表搜索与批量删除

「列车作业计划」的列车列表首列支持复选和全选，列表上方可按车次、名称、列车类型搜索，忽略大小写；多个空格分隔的关键词会逐一匹配。全选仅包含当前筛选出的已保存列车，改变搜索条件会清空勾选；搜索隐藏当前展开列车时，同时收起其移动面板。

点击「删除所选」后确认删除数量，所选列车、关联移动和过程约束在同一事务中删除。取消或失败会保留列表与勾选；成功后清空勾选并刷新计划。列车模板和源作业过程不受影响。

`POST /OperationPlan/DeleteTrains` 接收 `instanceID、stationSchemeID、operationPlanID、trainIDs`，返回 `deletedTrainIDs、deletedCount`。接口校验实例所有者／管理员权限；任何选中列车已不存在或不属于当前计划时返回 409，本批不执行删除。数据库写入失败时全部回滚。

## 独立交互示例

在 `switchyard-vue` 中运行：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5188 --mode production
```

打开 `http://127.0.0.1:5188/dev/operation-process.html`。该页直接使用生产编辑器组件，但使用独立示例资源，保存仅保存在页面内存，刷新后恢复示例，不访问业务后端。示例包含 5 类活动、10 个事件及 5 条次序关系。

`http://127.0.0.1:5188/dev/operation-process-layout.html` 挂载真实的通过能力页面和两级选项卡，提供纯内存的实例、站场和作业模板。进入「作业计划 → 作业过程编排」可检查三栏布局、窗口缩放和旧选项卡切换，页面请求不会访问业务后端。

上述独立编排和布局示例均支持 `?lang=en` 英文预览，可检查圆形按钮提示、属性栏、对象列表和分隔条，例如 `http://127.0.0.1:5188/dev/operation-process-layout.html?lang=en`。

布局示例加 `?batchTrains=1` 可检查列车搜索和批量删除，加 `&failBatchDelete=1` 可模拟删除失败；数据均为可刷新恢复的页面内存示例。组合英文与批量删除预览可使用 `?lang=en&batchTrains=1`。布局示例的批量过程生成仅使用简化时间偏移检查界面，不能代替服务端约束排布验证。

站场内「加载示例」则只绑定当前方案已有的资源；缺少对应类型进路时，选定进路留空，供后续补充。正式保存的编排模板独立存储，不覆盖旧列车作业模板，也不自动生成或替换已排定列车作业。

## 数据与接口

模板作用域为 `instanceID + stationSchemeID + operationPlanID`，同时拥有 `id`、`name`、`description`、`revision` 及下列数组：

| 数组 | 主要字段 |
| --- | --- |
| `activities` | `id, name, type, minDuration, maxDuration, startEvent, endEvent, routeList, selectedRoute, trackList, selectedTrack, x, y` |
| `events` | `id, name, time, nodeID, nodeList（自动生成）, anchorList, selectedAnchor` |
| `precedences` | `id, leadingEvent, followingEvent, interval` |
| `anchors` | `id, name, trackID` |
| `routeAnchors` | `routeID, startAnchor, endAnchor` |

模板级接口位于 `/OperationProcess`：

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/GetCatalog` | 作用域查询参数 |
| GET | `/GetTemplates` | 作用域查询参数 |
| GET | `/GetTemplate` | 作用域 + `templateID` |
| POST | `/CreateTemplate` | 完整模板 JSON |
| PUT | `/UpdateTemplate` | 完整模板 JSON，携带读取时的 `revision` |
| DELETE | `/DeleteTemplate` | 作用域 + `templateID` + 当前 `revision` |

所有接口沿用现有认证与实例所有者／管理员权限。模板图保存前统一校验，拒绝跨站场引用、悬空引用、候选列表不一致、非法时长和循环次序。更新使用版本号，发生并发编辑时返回冲突，保留客户端草稿供处理。

四类对象还支持独立 CRUD：`collection` 为 `activities`、`events`、`precedences`、`anchors` 之一；每个请求均携带作用域查询参数，写操作再携带当前模板 `revision`。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/{templateID}/{collection}` | 获取对象列表 |
| GET | `/{templateID}/{collection}/{id}` | 获取单个对象 |
| POST | `/{templateID}/{collection}` | 请求体为新对象 |
| PUT | `/{templateID}/{collection}/{id}` | 请求体为修改后对象 |
| DELETE | `/{templateID}/{collection}/{id}` | 删除对象 |

独立对象写入成功后返回完整模板和新的版本号。通过独立接口新增活动时，先创建其起止事件；删除活动会清理不再被其他活动使用的事件及次序。删除锚会清理关联的备选项、选定值与进路起终点配置。独立删除仍被引用的事件会被拒绝；界面整体保存时可同时删除独立事件及其关联次序。

数据存储在新增的 `operationprocesstemplate` 表中，首次访问时自动创建，支持 SQLite / MySQL。原作业计划的复制、ID 修改和删除也会处理此表；模板内的站场资源引用不会被复制成新的站场设施。
