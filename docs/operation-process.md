# 作业过程编排

作业过程编排位于「通过能力 → 作业计划」，与列车模板、列车作业计划、计划图和分析子页签共同使用。**作业过程编排和列车模板属于车站方案**，供该方案下的各个作业计划共享；方案尚无作业计划时也可使用。完整业务流程见[通过能力使用指南](../doc/Capacity.md)。

## 使用

进入「通过能力 → 作业计划」，选择实例和站场方案，再进入「作业过程编排」。该栏目和「列车模板」只显示方案选择及共享范围提示，不要求选择作业计划。切换同一方案下的作业计划会保留模板、展开状态和过程编排草稿；不同方案的模板相互隔离。点击「加载示例」得到一个未保存的新模板；点击活动、两端事件圆点、次序箭头或锚标记，在右侧修改对象属性。编排内容撑满选项卡的可用宽高，从左到右依次为编排图、属性编辑和对象列表；活动、事件、次序、锚表格位于最右侧，可点选对象编辑。各栏独立滚动，窄窗口下保持并列并提供横向滚动。

顶部使用紧凑工具栏：模板名称显示在加宽的小尺寸下拉框中，旁边保留保存状态，新建、加载示例、保存和删除使用小圆形按钮，悬停或键盘聚焦可查看名称。模块标题、独立模板名称和对象总数不再重复占用顶部空间；右侧对象列表的标签仅显示「活动、事件、次序、锚」，不附带数量。模板名称仍可在属性编辑中修改。

编排图与属性栏、属性栏与对象列表之间提供统一的竖向分隔条，左右拖动可调整栏宽。分隔条可通过 Tab 聚焦，再用左右方向键调整；Shift 加大步长，Home / End 调整到最小／最大宽度，Enter 或双击恢复默认宽度。这些布局操作不会修改模板内容。

主界面右上角的 EN / 中按钮切换界面语言；编排工具、对象类型、属性名、空状态和交互提示提供中英文显示。活动名、模板名等业务数据按保存内容展示，不随界面语言自动翻译。

添加次序采用两步连线：点击「添加次序」后，仅活动的结束事件亮起；点击前序结束事件后，该事件变为实心圆点，仅其他活动的开始事件亮起供选择后序节点。悬停目标事件显示从结束事件指向开始事件的虚线箭头，点击目标后才新增次序并恢复正常显示，默认间隔为 0，可在右侧继续调整。Esc 或「取消添加次序」可放弃未完成的连线；同一活动的开始事件、结束事件、独立事件及与前序相同的事件不能作为此次连线的目标，连线过程中暂停其他对象的编辑和拖动。循环依赖及时刻约束仍由模板校验检查。

编排工具栏的「隐藏对象列表 / 显示对象列表」按钮切换最右侧列表，隐藏时画布自动扩展。重新显示后保留当前列表标签及对象选择；此开关仅改变页面布局，不产生模板修改。

移动活动包括 Arrival、Departure、Shunting、Locomotive，备选进路按同名进路类型筛选。Dwelling 使用备选轨道。所选进路、轨道、锚必须来自相应备选列表。模板使用当前站场方案的 Node、Link 和 StationRoute；当前代码没有独立 Track 表，因此 Track 引用现有 Link。不会向已有站场写入示例轨道或节点。

移动活动图形及活动列表显示全部备选进路名称，随属性修改即时更新，长名称换行，未选择时显示「备选进路：未设置」。属性面板不显示「选定进路」，每条备选进路的端点锚可在对应折叠项中单独配置。数据结构保留 `selectedRoute` 兼容已有模板，移出备选列表时清空该值；添加候选不会自动选定进路，也不会修改事件地点。

活动的开始、结束事件在创建时确定，属性面板仅作只读展示，保存接口也禁止更换已有活动的起止事件关联；修改活动名称时，起止事件名称自动更新为「活动名称开始」「活动名称结束」，事件 ID、时刻、地点和锚保持不变。事件属性不显示发生时刻，图中不显示「时刻待定」；既有非空时刻数据及校验仍保留。停留活动的备选轨道仅包含真实名称非空的轨道，`null`、空字符串或全空白名称均不允许，界面不显示「选定轨道」。数据结构保留 `selectedTrack` 以兼容既有模板，移出备选列表时会清空其选定值。未命名轨道仍可用于进路及锚引用。

事件地点改为只读的「备选 Node」：开始事件取所属活动全部备选进路的起点，结束事件取终点；相同节点去重，共享事件汇总对应端点，仅使用当前站场的有效节点。修改备选进路后即时更新，保存和读取时后端重新生成 `nodeList`，客户端提交值不能覆盖该规则。没有备选进路的停留或独立事件显示空列表。旧 `nodeID` 保留兼容但不再决定候选；候选非空时，事件锚必须连接其中任一节点，界面会清理因候选调整而失配的事件锚。

备选轨道选项、已选标签、停留活动图形和活动列表中的候选名称均直接显示 `Link.Name`，不以 Link ID 或「轨道 + 编号」补齐。图形中的备选股道随属性编辑即时更新，名称过长时换行，未选择时显示「备选股道：未设置」。成功加载站场目录后，旧模板中的未命名或已删除 Link 引用会从停留候选中移除，并作为未保存的草稿修正提示；保存该模板后才写入数据库。

时间采用**相对于模板起点的分钟数**，事件时刻可以留空。`interval` 是前后事件的**最小间隔分钟数**，服务端同时接受原需求拼写 `intervel`。设置事件时刻后，保存会检查活动时长范围及次序间隔。模板内的进路起终点锚配置均可留空。

## 从作业过程生成列车模板

在「列车模板」列表上方点击「从作业过程生成」，选择当前实例和站场方案下已保存的作业过程，然后生成。无需先创建作业计划。尚未保存的编排草稿不会出现在选择列表中。生成成功后刷新并展开方案共享的新列车模板，不覆盖已有模板，也不修改原作业过程。

按现有列车模板字段转换：每个活动生成一条作业模板，保留活动名称及全部备选进路；最小时长从分钟转换为整数秒并向上取整。停留活动尝试匹配已有的停留进路，进路必须恰好对应其中一条备选股道，不会把经过该股道的接发车进路当成停留进路。未匹配进路的活动仍会生成，并在结果中提示先补充进路再用于计划或求解。原有求解器对空进路候选会回退到全站候选，因此此提示需要处理。

作业排列采用活动起止事件和次序关系组成的事件图拓扑顺序；同序时保留稳定顺序，不使用画布坐标。原模型中的最大时长、事件时刻、次序间隔、并行关系和锚无法完整映射到现有顺序作业模型，仍保留在原作业过程，生成结果会说明这些限制。列车数量默认 1、列车类型留空、固定作业关闭，可在生成后继续编辑；旧字段长度上限导致的名称缩短会明确提示。

服务端 `POST /OperationPlan/GenerateTrainTemplateFromProcess` 接收 `instanceID、stationSchemeID、processTemplateID、revision`，无需 `operationPlanID`；只从数据库读取已保存版本，并在同一事务中新增列车模板及全部关联作业模板。源版本过期返回冲突，任一写入失败时全部回滚。响应为 `trainTemplate、movementCount、warnings`。

## 从作业过程批量生成列车作业计划

在「列车作业计划」中先选择目标作业计划，再点击工具栏的「从作业过程生成」，选择当前车站方案下已保存的共享过程，设置生成数量与时间范围。新入口向目标计划追加列车及其全部活动，不覆盖已有列车；旧「自动生成」入口仍按原有规则重建目标计划。数量为 1–1000，本批活动总数上限 20000，时间支持跨日（最多 7 天）。

多个列车的起点沿用原平均定位公式：按本批全部移动数计算均匀时间槽，预留最长最小时长，使用每列首个活动对应的槽位定位该列车的起点。固定满足约束的列车起点后，对同一列车的完整事件图统一求最早可行时刻，使各事件在全部约束下尽早发生。次序间隔为 0 且无其他约束阻碍时，前后事件直接衔接；最小／最大时长、相对固定事件时刻、共享事件和任意端点之间的最小次序间隔仍须满足。平均起点定位是排布目标，约束与时间范围是硬条件；不可行时整批回滚，不生成残缺列车，也不把并行关系强行改成顺序。初始排布不替代跨列车轨道电路占用冲突优化。

每列车在新增 `trainprocesssnapshot` 表中独立保存完整源过程、来源版本、活动到移动映射、排定事件时刻和停留股道选择。源过程后续修改或删除不会改变已生成列车。停留直接使用有名称的备选股道；移动选择满足事件地点和锚约束的备选进路，资源缺失时拒绝生成。选中列车后点击「过程约束」可查看全部对象；绑定过程的移动可在表格中修改作业时刻、进路和时长，也可在计划图中调整单个 Cell 的占用时刻；新增、删除或重排活动仍需修改源过程后重新生成。人工编辑不会修改原过程快照，后续能力求解继续使用快照中的完整过程约束。

`POST /OperationPlan/GenerateTrainOperationPlanFromProcess` 接收 `instanceID、stationSchemeID`、目标 `operationPlanID` 及 `processTemplateID、revision、trainCount、startTime、endTime`，从方案共享库读取过程并写入指定计划，返回完整当前计划及 `processConstraints、generatedTrainIDs、warnings`。`GetTrainOperationPlan` 同样返回约束快照。列车删除、计划复制／改 ID／删除、旧入口重建均同步处理计划内的快照，不修改共享模板库。

能力求解输入会读取完整事件图和精确时长范围，停留股道在求解内部映射到关联轨道电路，不写入虚构的站场进路。过程列车使用显式事件约束，普通列车继续使用旧连续移动规则；共享事件同时约束时刻及物理地点／锚。求解结果保存为饱和计划时保留约束副本与停留股道。含过程约束的求解任务需要模型版本 **2.0.0 或以上** 的 CapacityAgent，服务端会拒绝向旧版本提交，防止旧代理忽略约束。

## 中观作业计划图

图中用青绿色实线和淡绿色行底表示具名股道，股道展开后的端点沿用同一配色；其他节点（包括出入口）用灰蓝色虚线表示。左上角提供行类型图例，节点原有名称和编号保持不变。

“从作业过程新增列车”打开单列车生成对话框，可选择当前车站方案下已保存的作业过程，填写车次、名称、列车类型、过程起始时刻和最晚结束时刻。对话框列出该过程的全部活动：移动活动从各自的备选进路中选择，停留活动选择备选具名股道，也可选择该股道对应的单 Link 停留进路；源过程已固定的进路或股道保持锁定。多个候选时由用户选择，唯一候选自动填入。

点击预览后，后端按完整事件图校验节点衔接、锚、最小／最大时长及次序约束，并返回每项作业的起止时刻和 Cell 占用。预览不保存列车；修改过程、资源选择或列车信息后须重新预览，无法满足约束时显示原因。时间支持跨日，最晚结束时刻不晚于起始时刻时按次日处理，总范围最多 7 天。

`POST /OperationPlan/PreviewProcessTrain` 与 `POST /OperationPlan/CreateProcessTrain` 接收计划作用域、`processTemplateID、revision、train、originTime、endTime、selections`，其中每项选择包含 `activityID、routeID、trackID`。确认生成时重新检查来源版本与全部约束，在事务中一次追加列车、全部作业和完整过程快照，并返回后端计算的占用数据供图表显示。用户选择仅收窄该列车副本的资源约束，源作业过程保持不变；失败不保留部分列车，草稿可继续修改。初始排布不处理跨列车占用冲突，后续可执行能力求解。

“点选新增列车”会进入点选模式，临时显示所有节点并展开股道两端。按起点、终点顺序点选，每两个点建立一个 Movement，横坐标作为该端点的作业时刻（精确到秒）。图中用编号和虚线预览草稿，可撤回最后一点；完整点对达到一组后点击“完成点选”打开确认对话框。退出模式后恢复原股道展开和显示配置。

系统按真实起止节点及方向匹配进路，多个候选按进路 ID 稳定选择，未匹配时保留空进路。确认对话框可填写车次、列车名称和类型，增删、排序和命名作业，编辑起止节点与时刻，重新选择进路。点击端点旁的“在图中重选”会暂时返回图中，单击后回到原对话框并重新匹配该作业的进路；取消重选保留原作业。手工选择其他进路会同步其真实节点并保留时刻。

确认生成通过 `POST /OperationPlan/CreateTrainWithMovements` 在事务中一次保存列车和全部作业，前端为草稿固定列车及作业 ID，失败时保留草稿，重复提交同列车 ID 不重复插入。Movement 的 `StartNodeID` / `EndNodeID` 保存所选节点，进路为空也可生成并在刷新后继续显示作业线，此时 Cell 占用为空；匹配进路的节点和 Cell 占用由后端按真实进路生成。取消点选、取消对话框或切换计划不会保存未确认草稿。

纵轴按车站节点排列，每列车按 Movement 的 `SortOrder` 顺序连接起终节点；排序相同或未配置时保留原有记录顺序，调整时刻不会改变作业顺序。每段线的两端分别位于该 Movement 的作业开始、结束时刻。节点优先取当前进路的起终点；无进路的过程停留活动使用共享事件的已确定节点、事件指定节点或所选具名 Link 的两端。图形首尾保留斜线、箭头和车次号。

具名股道（Link）的两个端点默认合并成一条横线，左侧显示 `股道名称（节点1,节点2）`。双击股道名称展开成两个节点行，再次双击股道名称收起；切换作业计划时恢复默认折叠。展开后的节点优先显示绑定的进路起终点名称，括号内保留节点编号。折叠仅改变纵轴坐标，Movement 的真实节点和起止时刻保持不变。配置对话框可选择股道／节点，并用“上移”“下移”调整显示顺序；保存时按组展开成有序 `EndpointNodeIDs` 数组，沿用当前作业计划的配置存储，重载和复制计划均保留顺序。

工具栏提供“直线／折线”连线模式，默认直线连接 Movement 起终点。折线用一段水平线和一段竖线连接，水平段位于非股道节点所在行：从非股道节点进入股道时先横后竖，从股道驶向非股道节点时先竖后横。两端都是非股道节点时水平段放在起点行；两端都是股道节点（含停留进路）时保留直线。同一行或同一时刻的折线自然退化为水平线或竖线。股道展开后仍按真实股道端点判断，不以当前行名称或上下位置判断。切换模式仅改变绘图形状，抓手仍位于 Movement 的真实起终点，中间折点不增加抓手，首尾斜线及车次号保留。

选中列车后，每个 Movement 都有独立的开始和结束抓手，矩形中心与线段端点重合。水平拖动或左右方向键默认将该抓手对应的时刻以及同列车后续时刻按同一偏移量平移。后续按 Movement 的 `SortOrder` 和稳定记录顺序判断，不按时刻大小判断：开始抓手移动本作业的起止时刻及后续作业的起止时刻；结束抓手保留本作业开始时刻，移动本作业结束及后续作业的起止时刻。时刻有效但缺少绘图节点的后续作业也参与保存。按住 Ctrl 仅移动当前抓手，拖动中按下或松开 Ctrl 会立即更新预览；重合抓手可用 Tab 切换焦点。

松开鼠标后通过一次 `PUT /OperationPlan/EditMovements` 批量保存所有变化的作业，两端分别写入 `EarliestStartTime`／`LatestEndTime`。后端在事务中检查整批原始记录，任一并发冲突或写入失败都不保留部分更改。Cell 时刻由后端按既有规则更新，前端读取接口返回值。每次联动只占一个撤销动作，撤销／重做恢复整批时刻，并使用服务器返回的完整记录作并发校验。节点纵轴始终包含当前作业使用的全部节点，可在配置中额外选择其他车站节点。

同一列车的抓手若在操作开始时具有完全相同的时刻和显示坐标，默认一起平移，包括股道折叠后不同真实节点上的重合端点。若前一作业结束与后一作业开始重合，拖动后一开始端也会同步移动前一结束端；同一端点同时属于重合组和后续联动范围时只加一次偏移。重合成员在动作开始时固定，拖动途中经过其他抓手不加入；同一时刻但不同显示行、不同列车或仅因缩放看起来接近的端点不组成重合组。预览与保存使用同一份端点集合，一次保存和撤销处理整个变化集合。按住 Ctrl 时仍只调整当前端点；双击对齐仍仅修改当前端点。

双击开始抓手，将当前开始时刻对齐同一列车上一 Movement 的结束时刻；双击结束抓手，将当前结束时刻对齐下一 Movement 的开始时刻。相邻关系按真实作业记录的 `SortOrder` 和稳定记录顺序查找，包括未绘制的作业，不按时刻大小或画面上最近的抓手选择。对齐只改当前端点，参照端点和其他作业保持不变，以保证对齐后时刻相等。没有相邻作业、相邻参照时刻无效或已经对齐时，不发送保存；双击保存沿用已有接口和撤销／重做。

鼠标悬停事件抓手时，矩形填充为对应列车的颜色。在具名股道上的停留活动抓手右键可切换通过／到开：起止时刻相同时显示“通过变到开”，保留起点并将终点后移 2 分钟；起止时刻不同时显示“到开变通过”，把两端都对齐到较早时刻。到达末端或出发起点与紧邻停留活动在同一股道、同一时刻时，右键也可操作该停留活动，便于处理重合抓手。菜单转换仅修改这条停留 Movement，不联动其他作业；通过现有后端接口保存，保留小数秒和跨日信息，并支持一次撤销／重做。默认 Cell 占用由后端随作业时刻更新，已手工编辑的绝对占用按原有规则保留。

选中列车后，上下拖动股道上的作业线段可调整这次停靠的股道，没有单独停留 Movement 时也可拖动到达末端与出发起点之间的股道连线。目标必须是图中显示的股道行或其展开后的端点行，不能落到非股道节点行；未显示的股道可先在显示配置中加入。调整关联该次连续停靠的到达末端、股道内作业及出发起点，遇到未能绘图的中间 Movement 则截断关联范围，其他停靠和列车不受影响，所有 Movement 时刻保持不变。按原进路类型、目标股道及未移动的外端节点重新择路，优先保留最多原进路 Cell，候选相同时按进路 ID 稳定选择。任一关联作业缺少匹配进路时，提示目标股道和作业名称，整次调整不保存。

原过程生成的无进路停留作业，调整股道后使用目标股道已有的真实停留进路；没有该进路时同样提示失败，可在进路设计页生成停留进路。全部进路变更通过 `EditMovements` 一次保存，并作为一次撤销／重做动作。前端清除旧占用和旧偏移覆写，由后端按新进路计算并返回 Cell 占用。当前股道显示优先使用 Movement 真实进路，原过程快照保留生成时的记录；撤销会恢复原进路及原手工 Cell 时刻。

## Cell 占用时刻

作业计划、二维仿真、三维站场及占用时间参数的甘特图统一区分行类型：具名股道对应的 Cell 使用青绿色名称、双线标记与淡绿色行底，其他轨道电路区段使用灰蓝色虚线标记。工具栏显示图例，悬停行名称可查看关联股道名。分类依据 Cell 的实际 Link 引用及 Link 的非空名称，不以 Cell 自身名称判断；同一区段关联多个具名股道时会列出全部名称，换股道拖动仍仅允许无歧义的目标。

“作业计划图”的 GanttView 支持上下拖动停留事件切换股道：从停留占用块的主体开始拖动，纵向移动后锁定换股道模式，保持作业起止时刻不变。目标按站场 Cell 的 Link 引用判断，仅允许明确对应一个具名股道的轨道电路区段；咽喉等非股道区段、对应多个股道的歧义区段及图外位置均不能作为目标。拖动时高亮目标行并显示虚线预览，取消或无效落点恢复原位置。横向拖动及两端抓手继续调整单个 Cell 的占用时刻。

松开鼠标后，沿用中观图的连续停靠识别与择路逻辑，重新匹配停留及前后相连作业的进路；任一关联作业缺少进路时提示原因，全部保持原状。目标股道需已有真实停留进路，原本无进路的过程停留也按此规则处理。全部变更通过一次 `EditMovements` 事务保存，后端按新进路返回 Cell 占用，失败整体回退；成功后同步更新两个计划图，并作为一次动作纳入中观图的撤销／重做历史。

所有具体作业计划的 Cell 占用时刻由后端生成，保存在 `movement.CellOccupationsJson`，通过作业接口的 `cellOccupations` 数组返回。每条记录包含 `cellID、routeID、startSeconds、endSeconds、isInterruptCell`；时刻以计划第零天午夜为基准，单位为秒，支持跨日及小数秒。初始占用开始为作业开始加轨道电路开始偏移，初始占用结束为作业结束加结束偏移。列车类型专用参数优先，每个未配置专用参数的 Cell 回退到公共参数。停留活动直接使用所选具名 Link 对应的 Cell。

模板生成、作业过程生成、CSV 导入和求解结果保存均写入这一数据。旧计划首次读取时由后端补齐，迁移保留已有 Cell 偏移与站场图的人工时刻。已保存的占用时刻不会在每次读取时随公共偏移参数重新计算。计划复制、改 ID 和删除沿用作业记录的原有数据生命周期。

占用甘特图及二维、三维仿真的占用图直接读取后端 Cell 时刻，前端只作单位与坐标转换。在占用甘特图中拖动单个 Cell 的起点、终点或方块即可保存该 Cell 的绝对起止时刻；其他 Cell 和作业起止时刻保持不变。保存采用带原始记录的 `PUT /OperationPlan/EditMovements`，遇到并发修改返回冲突，写入失败整批回滚。

作业计划图和中观作业计划图提供「重新推算 Cell 占用时间」按钮，通过 `POST /OperationPlan/RecalculateCellOccupations` 仅提交当前计划范围。后端在同一事务中读取数据库最新作业起止时刻、列车类型、进路 Cell 及公共／类型专用偏移，重新计算并保存当前计划的全部占用记录，返回完整计划供前端刷新。该操作覆盖人工占用时刻及旧版作业级偏移，清除撤销／重做历史；作业起止时刻和源过程快照不变。任一记录计算或写入失败，整个计划的占用更新回滚。

修改作业起止时刻或列车类型时，后端更新未人工调整的占用，保留已明确调整的 Cell 时刻；变更进路时按新进路生成所需 Cell，并采用用户同时提交的时刻。能力求解从已保存占用推导相对于作业两端的精确偏移；含小数秒偏移的任务需要模型版本 **2.1.0 或以上** 的 CapacityAgent。求解后的 Cell 时刻直接保存到新计划中。

## 列车列表搜索与批量删除

「列车作业计划」的列车列表首列支持复选和全选，列表上方可按车次、名称、列车类型搜索，忽略大小写；多个空格分隔的关键词会逐一匹配。全选仅包含当前筛选出的已保存列车，改变搜索条件会清空勾选；搜索隐藏当前展开列车时，同时收起其移动面板。

点击「删除所选」后确认删除数量，所选列车、关联移动和过程约束在同一事务中删除。取消或失败会保留列表与勾选；成功后清空勾选并刷新计划。列车模板和源作业过程不受影响。

`POST /OperationPlan/DeleteTrains` 接收 `instanceID、stationSchemeID、operationPlanID、trainIDs`，返回 `deletedTrainIDs、deletedCount`。接口校验实例所有者／管理员权限；任何选中列车已不存在或不属于当前计划时返回 409，本批不执行删除。数据库写入失败时全部回滚。

## 独立交互示例

在 `switchyard-vue` 中运行：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5188 --mode production
```

打开 `http://127.0.0.1:5188/dev/operation-process.html`。该页直接使用生产编辑器组件，但使用独立示例资源，保存仅保存在页面内存，刷新后恢复示例，不访问业务后端。示例包含 5 类活动、10 个事件及 5 条次序关系。

`http://127.0.0.1:5188/dev/operation-process-layout.html` 挂载真实的通过能力页面和两级选项卡，提供纯内存的实例、站场和作业模板。进入「作业计划 → 作业过程编排」可检查三栏布局、窗口缩放和旧选项卡切换，页面请求不会访问业务后端。

上述独立编排和布局示例均支持 `?lang=en` 英文预览，可检查圆形按钮提示、属性栏、对象列表和分隔条，例如 `http://127.0.0.1:5188/dev/operation-process-layout.html?lang=en`。

布局示例加 `?batchTrains=1` 可检查列车搜索和批量删除，加 `&failBatchDelete=1` 可模拟删除失败；数据均为可刷新恢复的页面内存示例。组合英文与批量删除预览可使用 `?lang=en&batchTrains=1`。布局示例的批量过程生成仅使用简化时间偏移检查界面，不能代替服务端约束排布验证。

站场内「加载示例」则只绑定当前方案已有的资源；缺少对应类型进路时，选定进路留空，供后续补充。正式保存的编排模板独立存储，不覆盖旧列车作业模板，也不自动生成或替换已排定列车作业。

## 数据与接口

两类模板的作用域均为 `instanceID + stationSchemeID`。模板接口兼容接收旧客户端的 `operationPlanID`，但不按它筛选或保存模板；响应中的兼容字段为空字符串。作业过程模板同时拥有 `id`、`name`、`description`、`revision` 及下列数组：

| 数组 | 主要字段 |
| --- | --- |
| `activities` | `id, name, type, minDuration, maxDuration, startEvent, endEvent, routeList, selectedRoute, trackList, selectedTrack, x, y` |
| `events` | `id, name, time, nodeID, nodeList（自动生成）, anchorList, selectedAnchor` |
| `precedences` | `id, leadingEvent, followingEvent, interval` |
| `anchors` | `id, name, trackID` |
| `routeAnchors` | `routeID, startAnchor, endAnchor` |

`/OperationPlan` 下列车模板、关联作业模板的读取、新建、编辑、删除和排序接口也只需方案作用域，其中关联作业还需 `trainTemplateID`。生成、维护具体列车作业计划的接口仍需目标 `operationPlanID`。

模板级接口位于 `/OperationProcess`，下表中的作用域查询参数为 `instanceID、stationSchemeID`：

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/GetCatalog` | 作用域查询参数 |
| GET | `/GetTemplates` | 作用域查询参数 |
| GET | `/GetTemplate` | 作用域 + `templateID` |
| POST | `/CreateTemplate` | 完整模板 JSON |
| PUT | `/UpdateTemplate` | 完整模板 JSON，携带读取时的 `revision` |
| DELETE | `/DeleteTemplate` | 作用域 + `templateID` + 当前 `revision` |

所有接口沿用现有认证与实例所有者／管理员权限。模板图保存前统一校验，拒绝跨站场引用、悬空引用、候选列表不一致、非法时长和循环次序。更新使用版本号，发生并发编辑时返回冲突，保留客户端草稿供处理。

四类对象还支持独立 CRUD：`collection` 为 `activities`、`events`、`precedences`、`anchors` 之一；每个请求均携带作用域查询参数，写操作再携带当前模板 `revision`。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/{templateID}/{collection}` | 获取对象列表 |
| GET | `/{templateID}/{collection}/{id}` | 获取单个对象 |
| POST | `/{templateID}/{collection}` | 请求体为新对象 |
| PUT | `/{templateID}/{collection}/{id}` | 请求体为修改后对象 |
| DELETE | `/{templateID}/{collection}/{id}` | 删除对象 |

独立对象写入成功后返回完整模板和新的版本号。通过独立接口新增活动时，先创建其起止事件；删除活动会清理不再被其他活动使用的事件及次序。删除锚会清理关联的备选项、选定值与进路起终点配置。独立删除仍被引用的事件会被拒绝；界面整体保存时可同时删除独立事件及其关联次序。

作业过程数据存储在 `operationprocesstemplate` 表中，列车及其作业模板分别存储在 `traintemplate`、`movementtemplate`，支持 SQLite / MySQL。共享模板沿用原表结构，以空的 `OperationPlanID` 表示方案级归属。计划复制不会复制共享库，计划改名／改 ID 不会修改共享库，删除某个计划也不会删除共享模板；删除所属车站方案时才清理方案内的模板库。

旧版本保存在各个作业计划下的模板会自动在事务中迁移到所属方案。遇到重复 ID 时保留全部模板，为冲突项生成新 ID，并在名称中标明原计划；关联作业模板及必要的来源引用同步更新。任一迁移步骤失败时整批回滚。模板内的站场资源引用不会被复制成新的站场设施，已生成列车的历史过程约束仍保留。
