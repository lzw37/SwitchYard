# 通过能力分析与计划操作

[文档目录](README.md) · [English](../en/04-capacity.md)

本章说明从已建立的站场方案到作业计划、能力求解、图形调整、报告和仿真的完整流程。功能口径对应 2026-10-11 的仓库实现。过程模板的详细规则见[作业过程编排](05-operation-process.md)。

## 数据层级与准备工作

能力数据按“计算实例 → 站场方案 → 作业计划 → 列车 → 作业 Movement”组织。进路、占用参数、作业过程模板和列车模板属于站场方案；同一方案下的计划共享模板库。复制或删除单个计划不会复制或删除共享模板。

实例管理中的“复制实例”当前只新建实例元信息，不复制下属方案、图形和作业计划，不能当作完整备份。站场方案复制与作业计划复制有各自的数据范围。

在顶部选择启用且有权限的实例，再在各页面选择站场方案。模板编辑不要求存在作业计划；列车计划、求解和仿真需要明确目标计划。切换范围后应核对当前名称。

| 页面 | 用途与完成条件 |
| --- | --- |
| 车站布置图 | 建立并保存几何、节点、线路、设备及轨道电路区段 |
| 进路设计 | 定义起终点、搜索进路、配置进路类型和直接妨碍区段 |
| 计算参数 | 维护各进路、各 Cell 的开始和结束占用偏移 |
| 作业计划 | 编排过程、维护模板和列车、查看计划图及分析 |
| 模型求解 | 生成输入 JSON、选择在线 Agent、提交求解及保存预设 |
| 仿真 | 按已保存计划回放平面或三维站场 |
| 结果分析 | 独立页签仍为占位；实际分析在“作业计划”的子页签 |

圆形按钮可通过悬停或键盘聚焦查看名称。统一分隔条支持拖动、方向键、Shift 加大步长、Home/End 到边界及 Enter/双击复位。EN/中切换界面语言，业务名称不会自动翻译。

## 建立站场与进路

1. 在“实例管理”创建或选择实例。
2. 在“车站布置图”创建方案，导入 DWG 或手工画线，整理拓扑并保存。
3. 检查 Node、Link、Cell 和设备绑定。线段几何相交不代表已经建立节点连接；自动打断、生成节点、近邻节点合并后仍须复核。
4. 在“进路设计”配置起终点，也可按信号机和车挡自动配置。
5. 搜索单条候选或批量生成进路，核对类型、端点、途经节点/线路、道岔、信号机和 Cell。
6. 核对直接妨碍区段，保存进路。停留作业必须有真实停留进路；物理 Link 不能直接替代过程活动的进路候选。

“显示全图”按当前容器等比例缩放并居中，不改坐标。调整窗口或面板后可再次适配。区段名称字体、字号和颜色等方案样式随保存保留，其他二维视图加载同一设置。

拓扑改变会影响设备、区段和既有进路。删除绑定设备的节点时注意同步删除提示；修改后重新检查进路，不能仅凭画面相邻确认连通。

进路的“列车类型”支持多选：接车、发车进路可选“旅客列车”和“货物列车”；其他进路可选“客车（车体）”和“货车（车体）”。在同组内切换进路类别会保留选择，切换到另一组时会改为该组的默认选择。也可清空选择后保存。

新建、自动生成和导入生成的进路默认选中所属组的两种类型。升级后首次启动后端会自动为 SQLite／MySQL 添加 `stationroute.TrainTypes` JSON 数组字段，并为已有进路回填对应默认值；已保存的选择不会被重复迁移覆盖。

## 标定占用参数

每个车站方案可以保存多个计算参数集。在“计算参数”的参数集选择框旁，点击圆形齿轮按钮打开管理对话框，可新建、复制、重命名、删除或设为默认。在对话框中点击某个参数集的“复制计算参数集”图标，选择来源并填写副本名称，会完整复制各进路的公共参数和列车类型专用参数；副本独立保存，后续编辑或删除来源不会影响副本。新建和复制时均可将新参数集设为默认；删除默认参数集前须先指定另一个默认参数集。

选定参数集后选择进路，逐个检查实际途经和直接妨碍 Cell，设置开始、结束占用偏移并保存。占用时间图可拖动端点，也可统一偏移或按进路类型批量设置，操作仅作用于当前参数集。该参数集内列车类型专用参数优先，未设置专用参数的 Cell 使用同一参数集的公共参数。空参数集需要先生成或填写参数，也可直接复制已有参数集。

从列车模板生成计划时，可分别为各模板的列车选择参数集；从作业过程生成时，可分别为各过程选择。单列车新增和编辑也支持选择。未指定参数集时保留空值，作业计划列表不显示默认参数集名称；生成占用和实际计算时使用当前方案默认参数集。指定的参数集已删除或属于其他车站方案时，也使用当前方案默认参数集。修改列车所用参数集会重算其未人工编辑的占用时刻；改变默认参数集、编辑参数或删除参数集不会直接覆盖既有计划中已保存的占用时刻，需要时使用“重新计算占用”。

后端启动时会自动升级 SQLite／MySQL：新增方案内的 `calculationparameterset` 表，为 `stationroutetime` 和 `train` 添加 `CalculationParameterSetID`，将原有参数归入初始默认参数集，已有列车保留未设置状态，计算时使用默认参数集。复制车站方案会同步复制参数集、默认设置及全部参数。

求解时需要同步更新并重启 CapacityAgent（模型版本 2.4.0 或更新），以便按列车所选参数集读取占用参数；后端会拒绝将此类输入交给旧版模型。

```text
Cell 初始开始秒数 = 作业开始秒数 + 开始占用偏移
Cell 初始结束秒数 = 作业结束秒数 + 结束占用偏移
```

偏移可以反映提前锁闭、延迟解锁。正负号、秒与分钟、跨日信息都直接影响冲突判断。“牵引计算”当前使用前端样例生成曲线和时刻，不是正式牵引模型计算，不能用其输出替代参数标定。

## 创建与维护作业计划

进入“作业计划”，在“列车作业计划”中通过计划管理新建、选择、复制或删除计划。选择列车后展开其作业，维护名称、类型、候选/实际进路、最小时长与起止时刻；保存后再分析。

| 入口 | 数据来源 | 对目标计划的作用 |
| --- | --- | --- |
| 列车模板“自动生成” | 方案共享的传统顺序模板 | 按传统规则重建计划，使用前核对目标 |
| 列车模板“从作业过程生成” | 已保存过程 | 新增共享列车模板，不直接生成列车 |
| 列车作业计划“从作业过程生成” | 多个已保存过程及各自数量 | 向当前计划追加完整列车及独立过程快照 |
| 中观图“从作业过程新增列车” | 已保存过程、逐活动进路选择 | 预览后追加一列完整过程列车 |
| 中观图“点选新增列车” | 图上的起终点和时刻 | 确认后一次保存列车和全部作业 |
| 导入 CellOccupancy | UTF-8 CSV | 默认新建计划，也可追加当前计划 |

列车列表可按车次、名称、类型搜索，空格分隔的关键词逐项匹配。复选“全选”只选择当前筛选的已保存列车；改变筛选会清空勾选。批量删除作用于选中的整列车及其作业、过程快照，删除前核对数量。

### 导入 CellOccupancy CSV

在列车计划工具栏点击“导入 CellOccupancy”，选择不超过 5 MB、50,000 条占用记录的 UTF-8 CSV，先预览再确认导入。

```csv
TrainID,MovementID,MovementType,CellID,OccupancyStartTime,OccupancyEndTime
C2551,0,Arr,1G,02:09:00,02:14:00
C2551,1,Dw,1G,02:14:00,02:30:00
C2551,2,Dep,1G,02:30:00,02:33:00
```

同一列车、同一 MovementID 的多行是同一作业的不同 Cell，应包含真实占用的全部区段。预览中确认 Cell 对应关系、列车与作业数量，以及复用或新建的进路。新进路必须能在既有站场拓扑中形成路径；已有公共占用参数不兼容时会另建进路。

追加时出现重复列车编号会整批拒绝。预览后文件或相关站场/计划数据发生变化时需重新预览。正式导入在事务中保存新计划、进路及作业，失败整体回滚。

## 占用时刻与保存规则

实际计划的占用以 `movement.CellOccupationsJson` 保存，接口返回 `cellOccupations`。每条记录包含 `cellID、routeID、startSeconds、endSeconds、isInterruptCell`。秒数以计划第零天午夜为基准，支持跨日和小数秒。

生成、导入、求解结果保存都会写入占用数据。旧计划读取时由后端补齐；已保存记录不会每次读取都随公共参数自动变化。修改作业时刻或列车类型时，后端更新未人工调整的占用，保留已明确调整的绝对 Cell 时刻。

“重新推算 Cell 占用时间”使用数据库最新作业时刻、类型、进路和占用参数，重新计算当前计划全部占用。它覆盖人工 Cell 时刻、清除旧作业级偏移及撤销历史；作业本身起止时刻和源过程快照保持不变。整批计算/写入失败会回滚。

修改过程列车的 Movement 或 Cell 不会同步重写其完整过程快照。后续求解继续从快照恢复事件基准、时长范围与候选进路；Cell 覆写仅在相应进路和区段匹配时适用。需要变更过程定义时，编辑源过程并重新生成列车。

## 两种计划图

### 作业计划图

占用甘特图以 Cell 为行、时间为横轴，直接读取后端保存的占用时刻。具名股道对应区段以青绿色和淡绿色背景表示；其他区段使用灰蓝色标记。判断依据是 Cell 的 Link 引用及线路名称。

- 横向拖动方块或两端抓手仅改变该 Cell 的绝对占用时刻，不平移整条作业或其他 Cell。
- 上下拖动停留占用块可换股道。目标 Cell 必须明确对应一个具名股道，且具备真实停留进路及所需关联进路。
- 保存通过带原记录的批量接口进行；并发冲突或写入失败会整体恢复。Esc 可取消当前拖动。
- 自适应、X/Y 缩放和刷新与计算参数及仿真占用图共用交互方式。

### 中观作业计划图

中观图的纵轴是节点/具名股道，显示每项 Movement 的真实起终点和时刻。具名股道可折叠为一行，双击股道名称展开两个端点。显示元素与顺序按计划保存；作业正在使用的节点始终参与显示。

过程列车的细线按保存的事件次序绘制：严格次序为实线，最小间隔为虚线；普通列车按作业顺序衔接。连线可切换直线/折线，线条可按过程、进路类型或列车类型配色。显示作业时刻开关在事件附近标记分钟个位数，秒数不进位。

1. 点选线条可选中多列车，Esc 或空白处清空选择。
2. 拖动开始抓手，默认平移本作业两端及后续作业；拖动结束抓手，默认平移本作业结束及后续作业。这里“后续”按作业记录顺序。
3. 同列车在操作开始时完全重合的抓手默认联动；按住 Ctrl 只改当前端点，键盘方向键可微调。
4. 双击抓手按严格次序的规定间隔对齐相关事件，并沿事件有向关系传播；矛盾时取消整次调整。
5. 停留抓手右键可切换通过/到开；通过变到开默认增加 2 分钟，反向转换对齐到较早时刻。
6. 上下拖动停留线换股道时，过程列车按共锚关系联动相关作业；缺少任一匹配进路则整次取消。时刻保持不变。

图形调整不是完整过程约束求解。检查最小时长、次序和资源冲突后再用于结论。悬停活动线可查看实际占用交集形成的冲突明细，即使关闭冲突高亮也可查看。

批量调整一次保存、一次撤销。Ctrl+Z/Ctrl+Y 的历史最多 20 个动作，换计划、重新打开或外部数据改变会清空；输入框内快捷键由输入框处理。换股道会重算占用，撤销可恢复原进路及人工时刻。

## 求解与饱和计划

启动独立 CapacityAgent 并连接当前服务。浏览器负责提交和展示；实际混合整数模型由 Agent 的 OR-Tools 执行，优先使用 SCIP，不可用时尝试 CBC。

1. 在“模型求解”选择站场方案与计划，点击“生成输入”，核对 JSON 的计划范围、列车、候选进路及偏移。
2. 选择在线、有权限且有空闲任务槽的 Agent，选择 `station-capacity-v1`。
3. 设置左右时间容差、时限、线程数和目标，提交并观察任务状态。
4. 检查结果 `hasSolution` 与 `status`，下载需要保留的结果 JSON。任务完成不保证有可行解。
5. 保存求解预设；在“作业计划”顶部选择预设并点击“生成饱和计划”，将通过校验的可行解另存为新计划。

当前模型版本为 **2.3.0**。过程地点/锚语义需要 2.2.0，严格等式次序需要 2.3.0，小数秒占用需要至少 2.1.0。混合这些功能时统一使用当前 2.3.0 Agent。输入 JSON 的 `minimumModelVersion` 在含小数秒偏移时可能显示 2.1.0，但服务端派发前还会读取完整过程与严格次序，按较高的 2.2.0/2.3.0 门槛校验，不能只看该字段判断兼容性。

默认设置为左右容差各 50,400 秒、时限 3,600 秒、12 线程、`min-end-time`。实际线程数还受 Agent 每任务 CPU 配额限制。求解目标分别为：

| 目标值 | 最小化内容 |
| --- | --- |
| `min-end-time` | 全部作业结束时刻之和 |
| `min-duration` | 全部作业持续时间之和 |
| `min-start-and-end` | 全部作业开始和结束时刻之和 |

普通列车使用相邻作业的顺序与进路连接约束，作业变量受一天范围限制；过程列车使用事件图、时长上下界、固定事件、严格/最小次序、共享地点及锚，范围最多七天。不同列车使用同一 Cell 时必须错开占用；当前该互斥逻辑跳过同一列车的作业组合，并非同车内部所有资源冲突的检查器。

普通求解任务和结果保存在服务内存中，不自动更新计划，服务重启后不能依赖任务记录恢复。饱和计划保存会创建新计划，保留求解后的活动时刻、实际进路、Cell 占用及过程快照；源计划保持原样。它对既有列车求解，不自动增发列车寻找最大开行数量。

结果中的 `totalOccupationTimeSeconds` 实际取所有占用结束时刻的最大值；`capacityValue = 列车数 × 64800 ÷ 最大占用结束秒数`，分母非正时为 0。该值受计划时间原点影响，不能当作全站最大能力或与下述瓶颈口径混用。

## 能力分析与报告

在“作业计划”中查看占用时间表、瓶颈分析和分类汇总。先统一总统计时间 `T` 与空费系数 `α`，刷新或计算后核对结果。

```text
K(Cell) = 非固定作业占用总秒数 / [(1 − α) × (T − 固定作业占用总秒数)]
进路瓶颈 = 该进路相关区段中 K 最大的区段
进路能力估算 = 进路作业次数 / 瓶颈 K
```

这是对各作业占用时长求和的统计口径，不是时间区间去重后的实际忙碌比例。没有有效分母或利用率时不应把空结果解释为无限能力。分类汇总按关联进路聚合；进路重复归属不同分类时不能再简单相加作为全站总能力。

分析快照及显示设置可保存；修改计划后重新计算，注意区分历史快照和当前计划。中观图工具栏提供 Word 能力报告导出，内容涵盖过程、计划图、占用、瓶颈和分类汇总，保留当前图形配置。报告使用完整提供的数据，不受列表搜索或选中列车限制；历史快照会标注来源。目前报告正文为中文，切换英文界面不会自动生成英文报告。

## 平面与三维仿真

进入“仿真”选择方案、计划和列车。平面/3D 切换共享进度、速度、作业序列、甘特图及单列车/全站范围；离开页签时暂停。默认播放速度为 60 倍，可播放、暂停、复位或拖动时间滑块。

同时进行的多个活动分别高亮；接车为红、发车为蓝、机车为绿、调车为黄。真实停留进路按原计划停留时刻显示，列车在股道中央静止，提前办理的发车进路可同时显示。3D 提供车型、显示比例、标签和占用选项。

回放用于观察已有时序和路径，不自动求解或修复冲突。显示异常时先检查计划、真实进路、Cell 时刻、拓扑和节点，再刷新。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 空列表或按钮禁用 | 检查实例启用状态、权限和方案/计划选择 |
| 停留候选缺失或换道失败 | 在进路设计建立真实停留进路，检查类型与关联接发/调车进路 |
| 参数已改但占用未变 | 已保存 Cell 时刻不会自动刷新；确认影响后使用重新推算 |
| 拖动后下一次求解恢复旧基准 | 过程快照与 Movement 编辑独立；核对源过程和快照 |
| Agent 不可用 | 检查连接、授权、任务槽、CPU/内存余量和模型版本 |
| 无可行解 | 检查时间容差、时长、严格次序、候选进路、锚和占用偏移 |
| 求解结束但仿真未变 | 普通求解未保存计划；生成饱和计划并选择新计划 |
