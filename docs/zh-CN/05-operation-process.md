# 作业过程编排与列车生成

[文档目录](README.md) · [English](../en/05-operation-process.md)

作业过程用活动、事件、次序和锚描述一列车的完整作业约束，支持并行活动、时间上下界和备选进路。本章对应 2026-10-11 实现，说明如何保存模板、生成实际列车以及理解后续编辑和求解的边界。

## 适用范围与对象

入口为“通过能力 → 作业计划 → 作业过程编排”。先选择实例和站场方案；过程模板和列车模板由方案共享，不要求先建计划。生成实际列车时才选择目标计划。

| 对象 | 业务含义 | 主要字段 |
| --- | --- | --- |
| 活动 Activity | 接车、发车、调车、机车、停留中的一项作业 | `type、minDuration、maxDuration、startEvent、endEvent、routeList` |
| 事件 Event | 作业开始或结束的时间/地点边界，也可为独立事件 | `time、nodeList、anchorList` |
| 次序 Precedence | 两事件之间的时间约束 | `leadingEvent、followingEvent、interval、isExact` |
| 锚 Anchor | 每列车统一选择的停留地点 | `routeIDs、dwellingActivityID` |
| 进路端点锚 | 某候选进路的两端分别采用哪个锚 | `routeID、startAnchor、endAnchor` |
| 模板 Template | 上述对象集合及版本 | `id、revision、activities、events、precedences、anchors、routeAnchors` |

模板中的时刻、时长和间隔单位为**相对分钟**；实际计划和求解输入使用秒。传统 Movement 的最小时长以整数秒保存，转换时向上取整，完整过程快照仍保留原始精度与最大时长。

五种活动统一选择当前方案的真实 StationRoute：`Arrival、Departure、Shunting、Locomotive、Dwelling`。停留活动也用停留进路，不使用物理 Link 作为执行资源。实际所选进路统一保存为 `selectedRouteIDs`。

## 编排一个过程

1. 点击新建或加载示例，填写模板名称；加载示例产生未保存的新模板。
2. 添加活动，设置类型、名称和最小/最大持续时间，选择该类型的备选进路。
3. 点击活动端点检查事件的备选 Node 和备选锚。备选 Node 由进路端点自动推导，不能直接改写。
4. 点击“添加次序”，先选前序活动结束事件，再选另一活动开始事件；界面预览箭头，点击目标后才创建。
5. 在次序属性中设置最小间隔或严格等于，以及分钟数。默认是至少间隔 0 分钟。
6. 核对停留自动锚和各候选进路的端点锚。需要其他共享地点时添加手工锚。
7. 保存模板，再执行生成或预览。草稿可以保存，但保存成功不代表已具备可执行的完整约束。

图中严格次序使用实线，最小间隔使用虚线。Esc 可取消尚未完成的连线。当前连线工具面向结束→开始；模型和既有数据还支持开始→开始、结束→结束等事件组合，后续处理不会用活动排序替代这些关系。

画布、属性、对象列表之间可拖动分隔条，支持键盘调整；对象列表可隐藏。图形位置只控制展示，不参与时刻排布。活动图形和列表显示全部备选进路，事件旁显示备选锚。

“复制作业过程”包含当前未保存草稿、全部对象、引用和画布位置，以新 ID 和版本 1 独立保存；名称追加副本及必要序号。失败时保留副本草稿。源过程及其草稿保持原样。

## 时间约束如何解释

```text
活动：60 × minDuration ≤ t(end) − t(start) ≤ 60 × maxDuration
最小次序：t(following) − t(leading) ≥ 60 × interval
严格次序：t(following) − t(leading) = 60 × interval
非空事件时刻：t(event) = 列车基准秒数 + 60 × time
```

严格间隔为 0 表示同时发生；最小间隔为 0 允许更晚发生。旧数据缺少 `isExact` 时按最小间隔解释；接口兼容原拼写 `intervel`，输出统一为 `interval`。

活动起止事件在创建后固定关联，不能通过保存接口替换。改活动名称会同步事件名称，不改事件 ID 和其他约束。事件时刻当前不在属性表中编辑，但旧数据的非空时刻仍生效并校验。

生成校验拒绝缺失引用、无效时长、负间隔、循环依赖和不可行时间关系。严格次序会反向传递后序约束，必要时推迟前序事件；系统不会自动把等式放宽为下界。

## 地点与锚如何解释

次序只规定时间关系，不自动要求两个端点在同一节点或进路连续。地点一致性由共享事件和锚约束承担。

- 非停留活动的开始事件收集候选进路起点，结束事件收集终点。
- 停留进路不限定使用方向，起止事件都可位于其任一端；同端接发也可表达。
- 同一列车使用同一锚的事件必须选择该锚的同一条停留进路，两端节点都属于该地点。
- 多个备选锚表示可选项；候选列表有交集不表示全部锚自动合并。旧 `selectedAnchor` 或固定进路仍会限制选择。
- 多活动共用同一个事件时必须满足同一物理节点和锚选择，不能只满足时刻相同。

新增停留活动会自动创建专属锚，其候选停留进路与该活动同步，起止事件共用此锚。与停留事件直接建立次序后，邻接事件自动加入该锚；断开连接、删除停留活动或变更类型时清理派生引用，保留其他手工锚。

自动锚不可从锚表单独修改进路或删除，应在停留活动中修改。服务端保存和读取时重新推导备选节点和自动关系，不能通过提交手工字段覆盖。旧单值 `routeID` 读取为单元素 `routeIDs`。

## 三种生成方式

### 转为传统列车模板

在“列车模板”点击“从作业过程生成”，选择同方案已保存的过程及当前版本。成功后新增共享列车模板，不覆盖已有模板，不改源过程，也不需要目标计划。

每个活动生成一个传统作业，保留全部候选进路并把最小时长转换成整数秒。顺序取事件图的稳定拓扑顺序，不取画布坐标。最大时长、相对固定时刻、次序间隔、并行关系和锚无法完整装入传统顺序模板，界面返回转换警告。

列车数量初始为 1、类型留空、固定作业关闭。若需要保留完整约束，应直接生成过程列车。

### 批量追加过程列车

1. 在“列车作业计划”选定目标计划，点击“从作业过程生成”。
2. 对列表中的各个已保存过程填写数量；0 表示跳过。
3. 设置本批统一起止时间，核对源版本，提交生成。
4. 完成后检查新车次、每项作业、实际进路、占用及“过程约束”明细。

每行 0–1000 列，本批总数 1–1000，活动总数不超过 20,000。时间接受 `HH:mm`、`HH:mm:ss`、`D+天数 HH:mm:ss`；结束不晚于开始时增加完整天数直到晚于开始，相同钟点表示跨日。绝对排布终点不能超过第零天起 604,800 秒。

所有选中过程在一次生成事务内追加，任一过程校验、版本或写入失败会回滚本批。旧模板迁移在生成之前独立完成，已完成的迁移不随生成失败撤销。来源变化通常返回 409，应刷新模板和版本后重试。

每个过程分别沿同一个时间范围定位自己的列车，多个过程的首列可能同时出发。生成不优化新列车之间或与已有列车之间的 Cell 占用冲突。批量入口没有批次幂等键；响应丢失后先刷新计划，避免重复追加。

### 在中观图新增一列过程列车

点击“从作业过程新增列车”，选择已保存过程，填写车次、名称、类型、过程起始时刻及最晚结束时刻，并为每项活动选择一个允许的进路。唯一候选自动填入，源过程固定的选择不可更改。

点击预览检查完整事件图、资源、锚和时间约束；预览不保存列车。修改任何输入后重新预览。确认生成再次检查版本和约束，一次写入列车、全部作业与独立快照。指定基准时刻不能由排布器自动移动；不可行时须调整输入。

用户选择只收窄该列车快照的候选，不修改共享模板。列车 ID 冲突会拒绝重复写入；失败保留草稿供修改。

## 初始排布算法

设某一个过程有 `A` 项活动、生成 `N` 列车，范围为 `[S,E]` 秒，活动最小时长的最大值为 `D` 秒：

```text
available = max(0, E − S − ceil(D/60) × 60)
slot = N×A > 1 时 available/60/(N×A−1)，否则为 0
第 i 列的目标基准 = S + round(i×A×slot) × 60，i 从 0 开始
```

目标基准是整分钟排布目标。批量排布将它调整到事件图允许的最近基准；确定基准后，用差分约束统一求全部事件最早可行时刻。活动最小/最大时长、固定时刻和严格/最小次序一起生效，并行关系保留。

例如接车 2 分钟、停留 8 分钟、发车 1 分钟，固定时长、零间隔依次衔接且资源可行，在 08:00–09:00 生成 2 列时，目标基准为 08:00、08:31，各列持续 11 分钟。该示例只说明定位公式，不代表无跨列车冲突。

资源按列车序号从候选中轮换初选，回溯寻找满足共享事件和锚的组合；不按负荷或交叉冲突最优化。单列车资源尝试上限 100,000，单次过程排布的差分图松弛预算 100,000,000；超限时减少数量或候选复杂度。

## 实际计划保存什么

| 记录 | 保存内容 |
| --- | --- |
| `train` | 实例、方案、计划中的列车身份、车次、名称和类型 |
| `movement` | 活动名称、进路、最小时长、起止时刻、顺序、实际节点及 Cell 占用 |
| `trainprocesssnapshot` | 完整源过程副本、来源 ID/版本、基准秒数、事件秒数、活动到移动映射、实际进路选择及显式次序 |

快照按实例、方案、计划、列车定位。源过程后续修改或删除不改写已生成列车。旧字段仅容纳 50 个 UTF-16 单元的名称会按完整 Unicode 文本元素缩短显示并返回警告，完整名称仍在快照中。

计划次序显式保留 `id、leadingEvent、followingEvent、minIntervalSeconds、isExact`，秒数保留小数。旧计划缺少此列表时从自身快照恢复，不依赖当前共享模板；不一致的显式记录会被拒绝。

删除整列车、复制/改 ID/删除计划以及旧自动生成入口都会维护快照生命周期。过程列车不能单独新增、删除或重排活动；应修改源过程并重新生成。

## 编辑后的求解含义

可以在明细表编辑既有 Movement 的时刻、时长和进路，在占用图中调整 Cell，在中观图中调整事件或共锚股道。这些操作保存实际计划，不自动改写原过程约束。

| 操作 | 实际变化 | 后续求解含义 |
| --- | --- | --- |
| 调整一个 Cell | 保存该 Cell 绝对起止时刻 | 输入据此推导匹配进路/区段的偏移 |
| 编辑 Movement 时刻、进路、时长 | 保存 Movement 字段 | 完整过程快照仍恢复原事件基准、时长范围和候选 |
| 修改共享过程 | 增加模板版本 | 已生成列车不变 |
| 保存求解后的饱和计划 | 新计划 Movement、Cell 和执行快照 | 使用求解后的事件时刻与进路 |

因此，手工图形看起来合理不等于满足完整过程。查看“过程约束”时，应将快照事件与当前实际计划区分；需要改变下一次求解依据时，应修改过程并重新生成。

当前模型为 `station-capacity-v1` 2.3.0，支持严格间隔和停留进路锚。模型兼容及实际版本校验见[通过能力求解](04-capacity.md#求解与饱和计划)。

## 保存校验与规模

模板存储允许未完成业务配置，但要求数组、ID、有限数值等结构有效。完整预览/生成另行要求可执行的名称、类型、资源和约束。

| 项目 | 当前上限 |
| --- | --- |
| 模板及对象 ID | 100 字符，无首尾空白 |
| 名称 / 说明 | 200 / 4000 字符 |
| 活动 | 2000 |
| 事件、锚、进路锚配置 | 各 4000 |
| 次序 | 10000 |
| 批量列车 / 活动总数 | 1000 / 20000 |
| 实际过程时间范围 | 第零天午夜起七天以内 |

模板带 revision 保存，过期版本不能直接覆盖新版本。并发冲突时重新读取并合并自己的修改。旧按计划存储的模板会迁移为方案共享；旧股道引用转换为真实停留进路前会保存备份，歧义会中止事务，不猜测资源。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 已保存但生成失败 | 保存允许草稿；补齐进路、名称、时长及事件约束 |
| 停留活动找不到资源 | 检查真实停留进路和类型，不能只给物理线路命名 |
| 次序相连却未在同一股道 | 次序只管时间，检查自动或手工锚 |
| 同锚候选很多仍不可行 | 必须找到一条停留进路满足同列车全部相关事件 |
| 多过程生成后列车重叠 | 各过程独立定位；再执行跨列车能力求解 |
| 严格次序拒绝生成 | 检查等式间隔、固定事件和最大时长是否矛盾 |
| 源过程修改没有更新列车 | 执行快照独立保存，重新生成所需列车 |
| 网络失败后不确定是否生成 | 先刷新目标计划检查，再决定是否重试批量入口 |
