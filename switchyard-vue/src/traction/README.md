# 牵引计算前后端接入

运行曲线由后端 `SwitchYard.SpeedProfile` 计算。前端保留站场拓扑展开、参数编辑、图形渲染及服务端采样点的光标插值；不再生成牵引/制动速度曲线或绝缘、轨道电路占用结果，服务不可用时不回退到浏览器求解。

## 接口

`GET/PUT /api/SpeedProfile/workspace` 按实例、站场方案、计算方案和进路记录读写关系化牵引参数；`POST /api/SpeedProfile/workspace/calculate` 校验已保存版本，计算并原子保存输入及结果；`GET /api/SpeedProfile/workspace/calculation` 读取最近结果。沿用应用 JWT 与实例 Owner/Admin 权限。原 `/api/SpeedProfile/calculate` 保留为兼容的无状态计算接口，牵引页面已不再使用。完整契约、单位、错误格式及示例见 [后端 API 文档](../../../SwitchYard.WebApi/SwitchYard.SpeedProfile/API.md)。

- 前端输入采用 m、s、t、kN、km/h；Davis 系数使用 `R(kN)=A+B*v(km/h)+C*v(km/h)^2`。全部 SI 换算在后端完成，尤其 `B*3600`、`C*12960`。
- 牵引表速度从 0 严格递增、力非负非递增；制动、阻力也为速度—力表，允许力随速度增减。三表均分段线性插值，表尾以末点力延伸。恒定制动力和 Davis 系数仅用于显式生成表格，每 10 km/h 取点并包括最高速度；有离散表时不直接使用生成公式计算。
- 每段可编辑坡度、限速及附加阻力 kN；可增加沿进路里程的停车点和停时。
- 允许速度按阶梯锚点编辑：点击限速线进入编辑模式，双击限速线插入锚点，拖动调整位置和速度，右键锚点打开删除菜单（也支持 Delete）。Esc 或点击图面其他位置退出并隐藏抓手；视图不显示编辑按钮或数值输入栏。0 m 首点保留；每点控制其后到下一点前或终点的限速。最多 1000 点，按当前方案和进路保存为关系行；分割限速时保留原坡度和阻力边界。上图不绘制绝缘，信号只显示自身名称，道岔编号加“岔”。
- 初末速度、步长和点数预算均传入后端。接车末速固定 0，发车初速固定 0；预算包含停车产生的重复里程点。
- 界面维护与摘要均使用回转质量系数 `γ`（0～2），有效惯性质量为 `m × (1 + γ)`。保存及 API 中的 `rotatingMassFactor` 仍表示倍率 `1 + γ`（1～3），读入时减 1、编辑时加 1；已有 1.08、1.1 分别显示为 0.08、0.1，历史数据与结果无需迁移或重新计算。
- 车长用于车尾出清及解除限速。坡度/附加阻力按车头所在段的单质点模型处理，非零坡度结果显示该假设。
- `durationS` 含停车时间；`runningTimeS` 是纯运行时间；`totalTimeS` 还包括办理进路及反应时间。停站处的重复里程点表示到达和停时结束。

## 接车制动预留段

接车计算前由后端复用现有反向制动包络，计算当前列车最高速度至 0 的制动距离，将其追加到进路入口前。入口外沿用首段坡度及附加阻力；实际起点速度仍用运行设置。界面显示“入口前制动段”和延长后的展开长度；原进路设备、绝缘、区段及停车点同步平移。前端只平移显示坐标，不计算制动距离。自动追加段不可编辑限速，原进路限速编辑坐标在提交时换回原坐标。旧快照保留，点击“计算”后应用新规则。工具栏“显示站外内容”默认开启；关闭后将入口前制动段从上下两图隐藏，站内进路铺满横轴，保留原位置与时间坐标。开关只控制显示，联动光标与限速编辑使用可见范围，不触发计算或修改已保存参数、结果。

接车的下方时刻图以黄色矩形显示每个轨道电路的接近时间：所有区段统一以车头刚进入整条接车进路的制动距离范围（已保存运行曲线的起点）的时刻为开始，各自以车头进入该区段的时刻为结束。所有黄色矩形的上边缘对齐，横向覆盖对应区段，悬停显示起止时刻及持续秒数。其上方依次为绿色进路办理矩形（0 至办理结束）和灰色反应时间矩形（办理结束至接近开始），宽度与对应轨道电路一致；零时长不绘制矩形。两段采用计算快照中的信号参数，未重新计算的编辑不会改变显示。区段占用矩形在车尾离开该区段时结束，之后至区段释放时刻单独绘制红色“释放时间”矩形；采用保存的退出与释放时刻，零释放延时或时刻未知时不绘制红色矩形，未出清区段仍以斜纹表示。显示只对已保存结果做时间插值，不触发后端计算；缺少制动距离、入口边界或完整运行范围时不编造接近时间。

## 占用参数回填

接车计算以车头首次进入站内进路起点、首次到达进路末端作为进路起止事件。所有途经区段从进路办理开始（0 秒）预先占用，开始偏移为 0 减进路开始时刻；结束偏移为释放时刻减进路结束时刻。最终停车时仍被列车覆盖的区段（含末端截断的区段）结束偏移为 0，只改变回填参数，不改写计算快照中的空释放时刻。缺失记录、异常时序及无法确定占用状态的区段保留原值。发车、通过计算维持车头物理进入相对进路起点出发的规则。参数表采用整秒，开始向下、已释放结束向上取整。只有用户点击“更新计算参数”才写入选定计算参数集；同时按进路结束减开始保存作业时间（秒，保留小数）。后端在同一事务中保存区段偏移与作业时间，响应同时确认两者。计算参数页用作业时间展开两个不同的时间基准，绘制前段、虚线和解锁段。

## 多套计算方案

层级为“车站 → 计算方案 → 进路记录 → 参数与结果”。同一方案可容纳多条进路，主进路与接续进路的组合分别保存，切换时恢复各自的参数、停车设置及曲线。“方案进路结果”可查看、切换、删除单条记录。工具栏“计算方案”选择同站场内的独立方案；“管理”支持新建、复制（含已有结果）、重命名、删除。至少保留一套，最多 100 套，名称不重复。方案列表和当前选择落库；切换前提交原方案待保存参数，失败时停留在原方案。所有工作区与计算请求均携带 `calculationSetID` 和 `routeCaseID`，计算只覆盖当前进路记录。整方案复制包含其中全部进路、参数和已有结果。新建方案没有结果，只有点击“计算”才生成；切换和管理操作不计算。旧版单套关系数据原子迁入默认方案，浏览器旧数据仅可迁入默认方案。

## 交互与参数迁移

页面载入、刷新和重新进入模块只读取数据库参数和最近计算快照；没有结果时显示可编辑限速及设备位置，占用图保留空态。编辑参数仍自动保存，但不触发计算。唯一计算入口是“计算”按钮：先保存当前参数，再请求后端计算并落库，成功后替换旧快照。输入变化取消在途请求并保留旧结果，标记“待计算”；失败也保留旧曲线。切换实例、方案时清理上一范围结果，版本检查防止迟到响应覆盖新范围。运行速度、占用图及导出使用快照自带的进路、车长及输入；允许速度线显示当前编辑值，更新占用时间仅在快照与当前输入一致时可用。

牵引业务数据不再写 localStorage。数据库无记录时只读旧 v1/v2 参数及列车预设，成功落库后移除旧记录；后续直接读数据库。完整参数和最近计算结果分别写入关系表，每套方案中每个节点、停车点、分段、采样点及占用时刻均为独立行，禁止 JSON/blob 文档字段。详见[关系存储设计](../../../docs/zh-CN/traction-database.md)。切换到已有进路记录时恢复其停车点；首次打开新的进路组合时清空继承的停车点，避免误用里程。

## 验证

在前端目录执行 `npm run test:traction` 和 `npm run build`。

后端接口测试使用隔离 Kestrel 进程，调用真实控制器、适配服务和计算库；测试认证仅存在于测试项目，不加载业务数据库：

```powershell
dotnet run --project SwitchYard.WebApi/SwitchYard.SpeedProfile.ApiTests/SwitchYard.SpeedProfile.ApiTests.csproj -c Release
```

核心数值测试继续由 `SwitchYard.SpeedProfile.Tests` 负责。接口测试覆盖认证、JSON 校验、SI 换算、模式边界、整列限速、停车及区段占用。前端回归覆盖参数快照、服务调用、取消、错误不回退及停站图表插值。
